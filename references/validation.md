# 验收规则

Phase 3 冻结适用规则时读取检查分类与第 11 节闸门清单；Phase 7 读取全部适用检查。本文件定义检查方法、PASS/FAIL、带证据的警告和回退阶段；可在授权范围内解决的问题必须在同一副本自动修正并重新验收，不向用户索要方案选择。

启用 `style-adaptation` 时，结构、Paint 存在性、素材和原材质保持检查只对[《画风迁移规则》](style-adaptation.md)中逐项登记的外观差异适用例外，转由 `styleAdaptationAudit` 验收。其他节点与所有业务/精确保护规则不变。

## 1. 执行链真实性

核对 `executionPhaseLog` 和真实写入集合：

```text
inspect → kv-style-check → kv-analysis → palette-proposal
→ palette-selected(user) → preflight → clone-and-kv
→ representative-trial → trial-review(pass)
→ expand → audit
```

必须先按[《执行工具》第 5 节](execution-workflow.md#5-执行覆盖严格验收与性能)核对冻结规则、全量颜色清单和完成目标，再证明：

- `kvStyleComparison` 在配色方案与任何写入前完成，包含新旧 KV 的画风差异证据及原 UI 冲突检查；模式不是仅由颜色、IP 更换或深浅变化触发。

- `preflightThemeDecision=pass` 早于首次 UI 写色。
- `sourceKvTone/sourceUiMode/targetKvTone` 均有独立证据；`paletteProposal` 的数量与角色符合《配色方案提案》，每套在展示前已绑定表面家族、`accentFamilyPlan`、`cardSurfaceStrategy`、`iconPairPlan`、目标显著性/明度拓扑、彩度/受光目标、面积化预览证据及 `proposalColorPreflight=pass`；`paletteSelection` 有用户明确选择，最终 `targetUiMode/hueStrategy` 与所选方案一致。最终主要 UI 表面实际呈现该模式，不能只改字段或被 KV 推断覆盖；`themeTransition` 由原稿与最终目标模式计算，相关 Icon／按钮及氛围规则使用同一模式。
- `representativeNodeIds` 早于代表试色产生。
- `representativeCoverage` 覆盖全部非等价按钮/氛围材质、状态及需要不同方案的背景；全页实际实例清单与最终上下文核对数量一致，不能只验一类代表。
- `representativeMutatedNodeIds` 只包含完整场景的白名单、必要后代及预登记共享背景通道；只读依赖不等于写权限。
- `trialGates` 有各场景真实上下文的 1:1、灰度、模糊和缩略图证据，整页图只作上下文检查；未扩展旧皮肤不在 Phase 5 冒充整页残留或美观 FAIL/PASS。
- 按[《局部试色与执行工具》](execution-workflow.md)第 2 节核对每批扩展对应的配方/依赖/映射指纹，门禁在该次写入前有效；历史 `trialGateStatus=pass` 不独立构成凭证。共享依赖变化后的相关实例均已更新和重验，无过期门禁。
- `expansionMutatedNodeIds` 来自后续独立写入调用。
- `buttonCompositeReview` 中声称已试色的版本均有同一副本、同一代表白名单的实际写入与截图记录；修正或比较结束后实际 Paint 对应最终选中版本。

任何事后补记、代表试色和全页扩展同调用、白名单外写入、过期门禁或缺少证据均为 `FAIL → Phase 4/5`。合法恢复/局部回退应追加实际事件并重验受影响依赖，不要求重做 clone。批次异常有新鲜读回和完成/待写/冲突分类，无未解决冲突；属性工具通过不能替代视觉通过。

## 2. 原稿与副本结构

用稳定 ID 重读原稿并与 `sourceAudit` 比较。原稿的父级、位置、尺寸、结构、文字、字体、素材、Paint、Effect、样式、变量、组件和旧 KV 必须完全不变。

快照/差异检查复用《局部试色与执行工具》第 4 节脚本；原稿策略不允许任何差异，副本只接受事先登记的确切前后值。保护检查优先于允许差异，采集错误、节点缺失、映射不完整不能被忽略。脚本未覆盖的特殊属性另取证；不从实际错误结果反推白名单。

按原稿→副本既有节点映射和子节点相对顺序比较副本；无新增节点时可直接比较索引路径。只允许：

```text
复制产生的新 ID
副本根 x
指定 KV IMAGE Paint 内容
kvFitPlan 白名单内的 KV IMAGE scaleMode/imageTransform 与专用载体 x/y/width/height
kvFitPlan 内最多一个绝对定位主图载体、一个环境补底节点或 Fill
启用独立主图载体后指定旧 KV Paint Alpha=0
mutationPlan 内颜色和 Paint Alpha
按《文字换色与恢复》逐项登记的普通 TEXT 自身 Alpha 覆盖（非状态/祖先/保护）
已登记的按钮材质 Fill/Stroke Paint opacity 或已有颜色 Effect Alpha 覆盖（保持原有效开关及不透明基底）
规则允许的跨模式 card.atmosphere 配方
dark-to-light 中已登记 remove-visually 的纯装饰 atmosphere Paint/色标 Alpha=0
已登记禁用按钮最小完整视觉单元相对正常态 50% 的 node opacity
light-to-dark 计划内 1px INSIDE 方向性描边
light-to-dark 收益卡最多一个底部氛围 Fill
有记录的实例本地覆盖与副本实例解绑
有证据的本次解绑新增、源实例不存在且隐藏无业务节点的结构恢复移除
有证据的 kv-asset-subtree 节点整体 Alpha=0
有记录的 theme-decoration-raster 滤镜/Paint Alpha
跨深浅模式 heroControlAdaptations 精确前景通道与必要的既有底托颜色/Paint opacity
```

每项 KV 例外必须逐节点/属性核对 `kvFitPlan.allowedMutations` 的前后值；新增节点只影响登记过的 KV 层，既有 UI 相对顺序不变。普通 TEXT Alpha 例外另逐项核对状态、保护区间、有效强度及字体/文案/几何零差异，不能豁免祖先或整个子树。禁用按钮节点 Alpha 例外只覆盖已登记的最小完整状态根，并核对未与既有状态衰减重复相乘。其他几何、布局、圆角、裁切、层级、顺序、混合模式、节点整体 Alpha、文案、字体、非 KV 素材、矢量/布尔/蒙版、共享样式/变量和主组件必须一致。矢量区域 Paint 与拓扑分开比较，允许的换色不误报成几何变化；原稿仍核对全部属性。不得因索引变化跳过 Hero 子树或原稿完整性审计。

逐项核对 `detachedInstances[].structureRecovery`：移除集合只包含有完整证据的本次解绑额外隐藏无业务节点，原有/有业务节点未删除；恢复后的数量和既有相对顺序与源实例一致，节点映射及受影响白名单已重新建立，解绑后的操作没有直接使用旧索引。旧 KV 标题/Logo 隐藏结果与截图逐项一致，不得以隐藏节点不参与渲染为由略过索引变化。任何误删、漏映射或沿用失效白名单为 `FAIL → Phase 4/6`，先恢复结构和映射再继续写入。

复合异形卡逐层比较 Z 顺序、节点/Paint Alpha、blendMode、mask 和可见轮廓。结构表面 Alpha 保持；已登记材质 Paint 强度差异逐通道验收，不误作结构变化豁免整个子树。出现后层透出、双影、接缝、脏边或前层半透明 Bug，`FAIL → Phase 6`。

## 3. KV 与图像

- 副本实际显示用户的新 KV，原稿仍显示旧 KV。
- `sourceVisualUnitType` 分类正确；若为 `composite-kv`，最终使用完整指定视觉单元或完整导出兜底，不是其中某个内层 IMAGE。整组原设计宽高、内部相对几何、裁切、文字、素材与 Paint 指纹保持。
- `kvLockedSubtreeRootIds` 与 Phase 4 冻结值一致；UI 颜色解绑、代表试色、区域写入、旧色扫描和自动修正的目标集合均与锁定子树零交集。最终内部 Paint、文字、素材、渐变、绑定与相对几何指纹必须完全一致；发生过误写后再调回也不能沿用旧 PASS，须由冻结快照重新证明零差异。
- `directFitCheck` 证明先检查了原尺寸/同宽使用；本可直接放入却人为缩小、为导航预留整圈边距，或随后补画构图，均为 FAIL。真实裁切导致的必要等比适配应有边界与截图证据。
- Hero 外框位置、尺寸、裁切、圆角、Auto Layout 占位及下方 UI 起点不变；图片适配策略和 KV 专属载体只按白名单变更。
- 默认保留原 KV 设计尺寸或页面同宽尺度，宽高比正确，允许超高部分仅从下方截去；不能为了完整显示尾部而整体缩小。记录实际可见/截去区域及标题、Logo、主体是否可见，关键内容意外被切须修正定位并复验。只有用户明确要求完整显示时，contain 分支要求整图四边完整。
- 新 KV 内置底部纯色/渐变的类型、`gradientTransform`、色标位置/Alpha、方向和实际终点与源复合视觉单元一致；页面延伸从真实终点继续。不得翻转或重建方向，不得叠加旧接缝造成断层。普通重着色只改计划内色值/Alpha，任何 transform 或色标位置变化均须有独立授权与前后证据。
- 实际截图确认主图经过全部祖先 clip/蒙版后符合已登记的尺度与下方裁切策略；contain 分支仍须整图完整；只设置 `FIT`、只检查节点边界或只比较 imageHash 均不足以通过。
- contain 留白/透明处没有旧图透出；必要环境补底来自新 KV 稳定环境色，位于主图后方且不越出 Hero，没有重复标题/主体或新造内容。无留白则无需补底。
- `protected-hero-controls` 按真实 `themeTransition` 逐节点核对：同模式全部外观样式精确保留，颜色变量/样式引用只在副本解除且不得改变有效显示色；跨模式仅《Figma 执行规范》第 5.4 节预登记的前景及必要底托通道可适配，读回校验目标值及必要性证据。未登记外观、几何、字体、文案、素材、状态、节点/祖先 Alpha 保持，不新增底板或间接覆盖。实际新 KV 宿主上的可辨性与第 5.1 节适用的对比度策略仍必验；跨模式不机械追平原稿比值。记为 `protectedHeroControlsAudit`，不存在时带证据记不适用。
- `kv-asset-subtree` 仅隐藏已经烘焙进新 KV 的旧视觉资产；倒计时、规则、状态、导航等 `hero-adjacent-ui` 仍可见可读。
- 每个 IMAGE Paint 已分类；内容、品牌素材与未知图片哈希未改变。

将上述结果记为 `finalAudit.kvFitAudit`。仅用户明确要求完整显示时，任何比例均可使用 contain；比例差异、留白或低源分辨率本身不判失败，源清晰度如实记录。只替换 imageHash 但截图仍显示旧 KV、存在非计划的祖先裁切、功能 UI 被遮挡/位移，或误改内容图片，`FAIL → Phase 4/6`，在同一副本自动修正适配，不因重设裁切/定位请求审批。

## 4. Paint 与视觉承载层

逐个检查 `visualSurfaceCarrierMap`：

- 需要换肤的卡片、容器、Tab、标签和按钮实际 Rectangle/Vector/Boolean/Ellipse/Frame 已进入目标色板；浅色撞色方案的卡片稳定底按 `cardSurfaceStrategy` 为低彩近白或纯白，主题色只出现在原有允许的卡顶氛围/Chrome；媒体、前三名颜色保护项与 `protected-marketing-banner` 须与原稿一致，不要求进入目标色板。
- 没有只改语义父 Frame 而漏掉异形承载层。
- 没有给 UI 空外层或更大无圆角兄弟节点新增 Fill，造成方形底、圆角丢失或边界扩大；已登记的 Hero KV 环境补底单独按第 3 节验收。
- 多层表面的 base、shadow、highlight、stroke、state-indicator 和 decoration 职责保持清楚。

同模式换肤逐节点比较 `paintPresenceMask`：除 `kvFitPlan` 逐项登记的 KV 例外和已确认的旧 `kv-asset-subtree` 外，Fill/Stroke/颜色 Effect 的存在、可见性、有效 Alpha 开关、Paint/Effect 类型、数量和顺序必须一致。原空通道仍为空，零贡献 Paint 未激活，可见 Paint 未删除/归零。UI 氛围渐变类型、方向、范围、色标数量和位置不变。

跨模式差异必须只出现在计划内节点并符合对应氛围矩阵。任何承载层漏改或无授权新增 Paint，`FAIL → Phase 1/6`。

## 5. 文字与对比度

对比度使用最终显示 RGB 和逐层合成背景：

```text
contrast = (L1 + 0.05) / (L2 + 0.05)
```

必须包含文字 Paint Alpha、文字节点/祖先 Alpha、表面 Paint Alpha、渐变最差点和下层背景。RGB 先转线性 sRGB 再计算相对亮度 L；图片或复杂渐变使用 1:1 截图采样最亮和最暗代表点。Paint 颜色、有效显示颜色和抗锯齿边缘不能混为一谈。

Phase 3 冻结 `contrastPolicy=source-baseline/contextual` 与 sourceUiMode、targetUiMode、adaptationMode 及理由。深→深、浅→浅且不涉及画风迁移时使用 `source-baseline`，真实可辨性与“不低于原稿对应对比度”同时必验；深浅转换或画风迁移使用 `contextual`，按新 KV、真实宿主、材质和角色确定目标，记录源/新比值但不以数值回退本身判失败。`4.5:1`、`3:1`、`7:1` 等 WCAG 固定数值仍仅作参考；用户明确要求 WCAG 或具体比值时另外记录 `contrastStandard=strict-standard`，两种策略都同时执行指定要求，不隐含要求 contextual 达到原稿极高比值。颜色可以根据 KV 调整，跨深浅可反转明暗方向；比较的是最终显示关系的比值，不是锁定旧 RGB、HSV V 或绝对亮度。

- 普通文字、规则、必读信息及小号说明须在实际尺寸、真实背景上清楚可读，正文强弱层级明确；不能只因比值低于参考值判失败，也不能仅凭比值高认定清楚。
- `targetUiMode=light` 时，普通 `textBaseColor` 的稳定基色默认须落在 HSB `B 18–32`，`text.primary` 为 `100%` 有效文字强度；白色、近白或浅色卡片上的主文案在 1:1 仍显淡时，即使理论对比度合格也为 FAIL，回到配方继续降低 B。`targetUiMode=dark` 时，普通 `textBaseColor` 稳定色标须为 `B=100`，`text.primary` 使用 `100%` 有效强度，次级层级通过有效 Alpha 建立；无已登记局部宿主例外却把深色 UI 普通文字基色降到 `B<100`，直接 FAIL。Hue/S 的微调不能代替这项模式分流。
- 金额、任务/作品中已确认的 `data.emphasis` 区间与顶部收益强调数据须鲜明、突出、清晰，不为追求参考数值压成灰闷深色。小号单位/说明与主数字分开判断，不把整段正文都升级为强调数字。
- 按钮文字与按目标模式和角色选定的主体联合验收；浅色 UI 的主要操作可使用鲜亮主体，或在偏浅宿主上使用有 KV/金属证据的干净深色主体，深色 UI 同样按宿主选择。同时检查渐变最亮端、最暗端和半透明合成点是否处于实际文字覆盖范围。远离字形的装饰亮边不充当文字背景，穿过文字的亮带不能遗漏。采样记录须包含坐标、对应文字节点及背景合成依据；不得把抗锯齿文字边缘误当作背景。
- KV 衔接文字、认证/状态、每种正文层级、Tab 和按钮文字分别抽检真实节点。
- `buttonTextPriority=vivid-contrast-white` 的特别鲜艳撞色按钮先用白/近白字完成真实 1:1 组合检查；白字在实际覆盖区对比度不足时再比较深字，保留白字截图、背景采样、失败原因和最终选择依据。其他按钮按已登记情境选择浅字或深字并检查实际材质、宿主和字号；不强制先试白字，也不按单一最高对比度数值自动定案。`gold-bright` 的默认深棕字按其专门规则验收。

数值参考来自 [W3C WCAG 对比度最低要求](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)。默认换肤不等同于 WCAG 合规验收。`strict-standard` 中依据用户要求判断字号、实际显示缩放、字重及真实语义豁免；不能把普通说明标成装饰来豁免，也不能用视觉通过冒充标准达标。精确保护文字保持原稿 Paint，必要冲突如实披露，不授权改保护色。

`textRampIntegrity`：先核对 `textTonePlan.targetUiMode / textBaseHsb / primaryEffectiveStrength / primaryHostClasses / overrides`。浅色 UI 的普通基色执行低 B 深色门禁，深色 UI 的普通基色执行 `B=100` 门禁；`text.primary` 均为 `100%`，`100/80/60/40` 仅是其余层级有效强度的起点，不重复乘入原节点弱化。真实背景需要的 Alpha/局部 RGB 差异分别登记 `textRampOverride` / `textBaseColorOverride`；普通 TEXT 自身 opacity 按 `textNodeAlphaOverrides` 逐项验收。层级必须真实清楚，但不能只因次级文字为 100% 就判失败；有依据的局部高 Alpha 不等于全页无差别拉满。按钮、链接、语义状态、标题和关键数据按独立角色验收；精确保护文字不套用新阶梯。

### 可读性修正与约束

文字实际难读时，确认限制来自 TEXT 自身、Paint 还是结构/状态祖先，按《文字换色与恢复》联合调整合法的文字方向、有效强度、背景与材质。40% 普通 TEXT 自身只是文字强弱时可使用最小 Alpha 覆盖；已清楚可读的文字不为跨过参考比值强行提高 Alpha 或压暗按钮。

`contrastAudit` 始终核验真实可辨性；source-baseline 另核验原稿基线，低于原稿对应比值即 FAIL；contextual 按冻结的情境目标、角色层级与已明确数值要求验收，不把原稿比值作为默认下限。未达到未指定的 WCAG 参考值本身不产生 FAIL；若记录了与标准的比较，须如实标明仅为参考及未满足的标准。结构/保护约束登记具体节点和实际影响；可读性、按钮显著性与材质或氛围干净度的真实失败仍须修正，不能以数值不再硬性要求为由放行。

`strict-standard` 下未达用户明确要求的节点不能通过警告豁免；保护/结构冲突须具体说明并请求必要选择，不改字体/布局兜底。只有启用标准验收时才记录各节点 `standardStatus=met/not-met/exempt` 及依据；默认模式不声称整页 WCAG 合规。

字体加载错误本身不属于对比度/文字完整性失败；以《文字换色与恢复》的实际颜色写入、读回、字体/内容/几何和截图证据判断。纯颜色路径未尝试或实际颜色未改不能算完成。

真实可读/可辨性失败、source-baseline 下对应合成对比度低于原稿，或 `strict-standard` 下未达用户明确要求时，`FAIL → Phase 3/5/6`；联合调整背景与文字，不得通过改字号、字重或布局兜底。默认模式禁止仅因未到 `4.5:1` 等参考比值触发回退或中止。

### 5.1 原稿对比度基线与可辨性

Phase 1 在 `sourceAudit.contrastRelationships` 建立实际存在的对应关系；Phase 3 将 ID、类型、节点范围与采样职责冻结进 `contrast-baseline` 机器规则的 verifier。覆盖文字/关键数据对宿主、页面/卡片/内部容器之间、Tab 选中与未选中表面、指示条对底色、功能 Icon 图形对底托、按钮/CTA 主体对宿主及标签对主体。精确保护对象仍保留原值，但其真实宿主变化也需核查并如实记录冲突。装饰高光与材料内部塑形色标不逐个升级为业务对比关系；实际不存在或无可见边界的关系在预检附读取依据，不在验收时删掉失败关系。

每个关系按实际材质/状态/宿主选择最少完整代表，登记全部实例→代表映射；非等价上下文分别比较，最终逐实例核对。记录相同角色、相同采样职责的源/新合成颜色与未四舍五入的比值。纯色 NORMAL 叠层可由快照中真实 RGB(A)、Paint/节点/祖先 Alpha 自下而上计算，不能漏掉宿主或重复乘 Alpha；复杂渐变、混合、IMAGE 和氛围采用真实 1:1 截图，保存坐标、像素比例、哈希与取样依据，排除字形边缘/抗锯齿。文字可用完整 Paint 与真实背景计算，不能从细字的抗锯齿像素推算全文颜色。

可辨性分别进入 `readability/surface-discernibility/state-discernibility` 的冻结视觉检查，逐实例范围独立覆盖，不能用一项的 PASS 代替另一项。

对比度只表示差异大小，不表示强调顺序。原稿中确实可比较、共享同一实际背景与采样职责的强弱关系，另建 `emphasisOrders`（格式见执行工具第 4.7 节）：比较强成员/弱成员各自对宿主的对比度之比，新稿须仍大于 1；仅 source-baseline 另要求不低于原稿的相对力度。适用的比值门槛与相对强弱不倒置同时通过，不能互相替代。不能把不同宿主、不同职责、窄装饰亮边或整个 CTA 的业务权重硬塞为同背景比值；多信号状态和材料层次仍以完整视觉单元验收。原稿没有该种顺序时不虚构数值约束，但不豁免真实状态层级。

同模式通常延续原稿的表面/材质明暗分工；跨模式或有依据的目标配方可以调整明暗方向，写入前明确作用与范围。高光仍承担受光、暗部仍承担塑形，选中信号与操作优先级不能倒置。原稿同色/接近的同族卡片仍延续相近基础表面，收益卡的光影差异不自动成为强反差深色底板。不能统一要求所有选中态变深或所有按钮变亮。

在覆盖文字的最亮/最暗背景、主体稳定区、边界附近与不同非等价背景中登记必要采样；source-baseline 下每个可比较样本均须满足 `newContrast >= sourceContrast`，不取平均、不删最差点、不用某处增强抵消别处减弱；contextual 下保留完整样本与源/新比值，验证目标宿主上的可读性、层级、材质和已冻结的明确数值下限，不因比值低于原稿单独回退。源/新原生截图量化口径一致，预留小幅余量后读回复算；仅容许计算浮点误差，不以四舍五入相等放行。跨模式原稿比值用于分析同一角色关系，允许前景/背景明暗方向反转，不要求追平旧极端值。系统状态栏时间/信号/电量作为独立覆盖角色：跨模式优先比较适合真实 KV 的深/浅前景，保持布局与内容，检查实际尺寸可读；不默认追赶原稿接近 21:1 的比值或新增底板。

同时独立验收：文字清楚、操作突出、状态可辨、容器范围可辨。source-baseline 下原稿比值很低时，不低于它只是必要条件；新稿仍看不清则 FAIL。仅换 H / 保留 S/V 与这条要求冲突时，联合调整合法的前景/背景，并记录覆盖依据、保持透明度/几何/材质/保护边界，使受影响门禁失效后复验。不要全页无差别压暗、增艳或新增描边兜底。

复用《执行工具》第 4.7 节严格重算，将结果写入 `finalAudit.contrastAudit`；任何缺关系/样本、过期快照、不可确定背景、违反适用数值要求或视觉不可辨均不能记 PASS。原稿保护或结构与要求确实冲突时保留证据、报告未完成，不能用警告豁免，也不擅自修改保护。

### 关系验收不得自证

最终关系复查回到原稿/新稿截图与用户规则，不把色板、已执行计划或此前 PASS 作为正确性的依据。至少核查实际存在的三类反证：

- 同族主要小按钮与 CTA 并排看彩色及灰度主体，是否一个明显重深、另一个轻浅，或主体色系漂移；检查现有渐变、反射与各自宿主，而不以 CTA 尺寸更大、文字清楚或同属暖色放行。全实例范围及主体 L*/色差进入 `button-appearance-family`，接受条件见颜色规则第 1、8 节。
- 连续 Tab 与内容区沿真实接缝查看最终合成颜色，是否外层一致但深层底板断色；用对应原生空白像素核验，不能仅比较裸 RGB 或文案。跨卡片同层级同状态 Tab 再并排查看完整状态语言。
- 卡片顶部/底部、CTA 下缘及外围宿主的宽渐变过渡区，是否出现无依据的暗带、灰脏反射或不协调色块；不能只看按钮内部亮点。启用渐变的零 Alpha 色标 RGB 不能按隐藏通道忽略。

## 6. 状态、Icon 与交互层级

### KV 与 UI 的颜色一致性

- 先执行 `heroBottomExtensionAudit`：复核底部环境/前景身份、延展资格、与其他大范围环境候选的比较和最终选择。若为 `selected-solid|selected-gradient`，页面接缝起点须匹配可见下缘并在 1:1 图中自然延续；若为 `eligible-not-selected`，须有整页环境、表面层级或舒适度上的更优证据及自然衔接方式；若为 `not-suitable|existing-transition`，须有纹理/前景或结构证据。不能因底部纯色自动锁定，也不能在底部适合延伸时无理由忽略接缝。

按《颜色决策规则》第 3.0 节生成独立的 `themeColorConsistencyAudit`。等价实例/连续表面的对应通道关系仍由 `colorRelationAudit` 检查，二者分别验收：

1. 核对 `kvAnalysis.colorAnchors` 的名称、原图坐标、真实像素、空间角色、连续面积/横向覆盖、实际可见 Hero 下缘接触、纹理具体程度、前景风险与延展适合度，以及 `surfaceFamilyPlan` 和角色 Recipe 的引用。主表面锚点须来自可延展环境，大面积连续背景优先于局部前景物；底部候选只有满足可见、连续、面积、颜色稳定/较纯和环境身份条件时才能因接缝优势提高优先级。样本与锚点名称/角色不符、没有来源依据或来源角色不匹配，返回 Phase 2/3，不以“位于底部”“同属暖色、材质相同”放行。
2. 将 KV 原始区域与最终页面背景、卡片、容器和主要按钮/CTA 并排看彩色 1:1。分开记录原 Paint RGB、最终合成代表样本与冷暖/色相倾向；不要从字形抗锯齿、亮边或最鲜艳像素取代表色。按 `surfaceFamilyPlan.hueRelationshipPlan` 检查：默认同一或相近色相家族，明度、彩度与材质仍须形成可辨层次和醒目操作，不能要求按钮与背景同 Hex。
3. 检查深浅转换后的环境家族是否仍成立，已有氛围/纹理/反射有没有把大面积颜色带偏。无金属 `contrast` 方案核对可靠 `surfaceContrastBasis`、约 180° 对向候选与 KV 高彩高明度候选的比较、`contrastDerivation=hue-opposition|kv-vivid-accent` 及可见色相分离；同一 Hue 仅深浅不同不能通过。金属方案核对 `metalAccentEvidence` 和 `buttonVariant`：`metallic-analogous` 对应本次金属家族，`gold-bright` 的主体中间调为正常明亮金黄且高彩度、受光面积充分，并落在类似 `#FFEED7→#FFC58A`、`#FFEEC6→#F9DB92`、`#FFE5A3→#FFC165` 的暖亮视觉范围而非机械固定值；`clean-deep` 有来源且不灰黑暗沉。暗铜、棕橙、土黄、只靠窄高光显金，或为迁就白字而压暗的 `gold-bright` 直接 FAIL。背景和卡片须保持已声明的连续环境家族，Tab 保持表面同系；功能 Icon 图形引用或有依据地派生自 `schemeAnchorContract.icon`，主要小按钮与 CTA 共同引用 `schemeAnchorContract.button`，不能出现黄/橙等可见分裂。同时检查 Icon/按钮与 KV/真实宿主是否协调。
4. 生成 `schemeAnchorConformanceAudit`：`background/card/number/icon/button/tab` 六个公开锚点都至少有一个稳定可见 `anchorId` 通道，实际目标 RGB 与用户选定方案逐通道一致。Tab 的主要选中底板不得改绑按钮/Icon 色，按钮/Icon/数字也不得只保持“同色系”却换掉代表值。锚点缺失、错绑或实际读回漂移直接 FAIL；若确需改变公开值，返回 Phase 2 重新展示并等待用户确认。
5. 核对 `accentFamilyPlan` 与最终稳定主体：普通功能 Icon 的稳定主体从背景/卡片的连续环境家族提取，不从孤立反光或按钮色倒推；深色 UI 的公开 `number` 与 `icon` 必须同 Hex/RGB，且高亮数字、Icon 的可见代表区域分别兑现该锚点。按钮可保留第二强调家族；浅色 UI 的数字可独立，但数字/Icon/按钮默认仍不超过两个显著高彩家族，第三家族只在事先有主题级 KV/业务/用户证据时例外。用彩色 1:1、模糊图及缩略图看重复 Icon 是否堆出新的焦点；小面积金属反射可有不同光色，但不得让它成为 Icon 主体。发现漂移时若六色公开锚点已经用户确认，不能静默改 Hex，须返回 Phase 2 重新展示受影响方案并确认。
6. 彩色模糊图与缩略图检查全页累计色彩面积：主家族仍须主导，局部植被/反光/强调色不能经过大面积和高频重复成为无依据的第二主底色；撞色方案仍须清楚呈现反差和面积主次。灰度用于明暗，不能代替这项彩色检查。

记录锚点、实际节点/区域、截图、合成贡献与结论。真实家族漂移或关键疑点未验证时为 `FAIL → Phase 3/5/6`；返回受影响配方并使相关门禁失效。文字可读、目标通道数值正确及原稿关系一致均不能覆盖该 FAIL。

先逐项对照 `themeDecision.colorClarityPlan` 与《颜色决策规则》第 3.1 节，生成 `finalAudit.colorClarityAudit`。必须正向确认以下五项均满足，并附节点/截图证据：实际彩度足以表达 KV 和角色；页面/卡片/容器对比清楚；主要操作突出且状态可辨；文字/图形清楚；整页强弱关系和材质表现美观协调。只有“未发现发灰/过艳”、只有文字对比度数值、只有少量高光像素颜色鲜明，都不足以通过。保护色不参与新彩度目标，按第 8 节验收原稿一致性。

继续按《颜色决策规则》第 3.2–3.3 节核对 `colorClarityPlan.lightnessAndChroma`，把结论记在同一 `colorClarityAudit` 中：色相、彩度、感知明度、材质和背景关系是否分别满足角色目标。所有模式中，只要三类角色同时存在，就须在同一真实宿主或可比场景中满足 `Icon 底托 < 选中 Tab < 主要按钮/CTA`；此顺序按最终合成后的色彩存在感、宿主分离、面积与边界综合判断，不要求单一数值机械递增。`targetUiMode=light` 时还必须单列验证：页面背景明亮且仍有明确主题彩度，没有淡到近白/灰雾；卡片比页面更亮、可接近白色且边界清楚；主要按钮/CTA 的 `buttonToneDirection` 与真实宿主相符，明亮方向有足够彩度，干净深色方向有 KV/金属来源并比明亮候选形成更清楚分离，且没有灰闷近黑或只靠亮边；功能 Icon 图形清楚，Tab 与 Icon 底托淡淡带色且不暗沉；Icon 底托即使忽略图形，在 1:1 下也与卡片可辨，不能浅到消失。发现问题或关键不确定项时，须有针对具体维度的真实对照试色、调整变量及结论，不能以其他维度达标代替验证。仅给 HSV 饱和度或仅说“饱满”不算证据；数值达标但视觉重量、受光或操作层级不合适，仍为 `FAIL → Phase 3/5`。授权参考设计师页面时，还须核对可见 Paint 与 IMAGE 分类、同角色比较、可迁移关系及结构/对比度限制；不得把未验证的参考数值视为达标。

再按第 3.2.1 节生成独立的 `finalAudit.hsbGuardrailAudit`。统一使用 Figma `H/S/B`（`B=HSV V`），按钮只标记为 `dark-ui-small-button / dark-ui-large-button / light-ui-small-button / light-ui-large-button` 四类；`dark/light` 指 UI 模式，不指按钮自身明暗。按钮自身另记 `buttonToneDirection=bright|metallic|clean-deep`。若仍使用旧的 `light/deep-button` 分类、把金属另建类别，或用共同阈值合并大小按钮，直接 FAIL。

每个适用尺寸逐个核对亮端、主体中间调、稳定暗端、包边/深度层、面积职责和排除项。普通鲜亮按钮的所有可见主体本色色标必须为 `B=100`；用户指定的暖亮金例外可为 `B98–100`。渐变稳定暗端只要仍承担主体本色，就不能因为“渐变需要层次”降到 77、83、91 或 96。除亮金近满明度容差外，更低 B 只有两条默认合法路径：深色 UI 中有可靠金属证据的金属主体/金属深端分段，或浅色 UI 的已选 `clean-deep` 按钮。前者须有金属来源与深色宿主清晰度，后者须有 KV 来源、比明亮方向更清楚的操作分离及真实小/大按钮分别试色；其余一律 FAIL。高光白、透明端、极小阴影和结构层不参与主体门禁，但必须单列。

`hsbGuardrailAudit` 必须分别产出当前模式的 `smallButtonSummary`、`largeButtonSummary` 和 `iconSummary`；另两类记 `not-applicable`。再单列 `buttonFamilyConsistency`，检查大小按钮是否共同引用 `buttonPrimary`、主体色相/中间调是否一致。普通鲜亮 Icon 的主体本色优先 `B=100`，并说明它从哪个连续背景环境锚点派生；深色 UI 另核对 `number=icon` 锚点精确相等。较低 B 只允许小面积塑形暗部或有证据的金属/深色 Icon。Icon 底托只验第 7.1 节相对合成关系，不误套按钮范围，也不要求按钮 B 高于 Icon B。

最终对用户总结时，`小按钮` 与 `大按钮/CTA` 必须分成两个小节，明确目标 UI 模式与各自的 `bright|metallic|clean-deep` 方向，并报告亮端、主体中间调、稳定暗端、包边/深度层、命中的四类范围、视觉结论与 PASS/FAIL；随后再给一条 `大小按钮一致性` 结论。不能新增“金属按钮类型”，也不能只报共同锚点、一个代表 Hex 或合并后的最低值。

验收强调色时同时核对饱和感/彩度与感知明度：有足够色彩力度，亮色鲜明、深色干净；不能以 HSV 饱和度高、文字对比度高或少量鲜亮像素替代真实观感。发现灰闷时分别定位彩度不足、明度压低或叠层冲淡，不默认只提高饱和度，也不把所有表面一起增艳。

### 关键数据

所有 KV 下，金额及任务/作品的强调数字按《颜色决策规则》第 6.1–6.2 节验收：颜色鲜明、突出、清晰，不因字号小而自动压暗为灰闷中间色。浅色 UI 的顶部收益卡可选鲜亮或干净深色；深色 UI 的高亮数字必须兑现 `number=icon` 共同锚点，不能为适配局部宿主临时产生第三色。逐文字区间记录真实可读性与强调效果；仅启用严格标准时附对应标准结果，数值较高不能覆盖强调不足、灰闷或融入正文的失败。

### Tab

- `control-family-consistency` 独立验收跨区域同族控件：内容分类 Tab、榜单 Tab 等按层级/状态配对看原稿与新稿，共同目标配方及登记变体均实际读回并在真实宿主验证。同族原本同色却因卡片划分被拆色，或虽局部可辨但跨区域色彩语言明显漂移，均 FAIL。不同层级/状态不要求全部一个 RGB；源 RGB 不同但应共用新配方时用目标值校验。该规则 scope 覆盖全部相关控件根，需一次完整跨区域比较，不拼接各卡片单独的 PASS。
- 核对 `sourceColorRelations` 的原稿关系、预先登记的语义拆分及实际读回结果，生成 `colorRelationAudit`。原稿连续同色底板不能因节点类型不同而拆色；同色文字的状态 Alpha、前后表面差异及指示条角色按《颜色决策规则》第 9 节复核。查看原稿与结果的 1:1 对照，不能只验文字或旧色残留。
- 一级/二级 Tab 在实际尺寸下一眼可辨；Tab＋连续容器与外卡、选中/未选中底色、指示条与底色、文字与底色分别通过原稿基线检查，不合并为一个文字比值。
- 现有结构支持时优先使用两类选中信号；只有单一状态载体时按《颜色决策规则》第 9 节验证一类明确、稳定的信号，不为数量新增结构。
- 选中态纯色方向弱于邻近主要按钮，不使用大范围材质渐变。
- 选中态引用 `schemeAnchorContract.tab`，默认与页面/卡片表面同色系；撞色按钮不自动授权 Tab 使用撞色。无用户明确要求或强业务语义证据而改用按钮撞色，记为 FAIL。
- `targetUiMode=light` 时，选中底板淡淡带有页面/卡片表面家族的颜色，并以边界、文字或既有指示条保持状态清楚；其颜色存在感须高于普通 Icon 底托、低于主要按钮/CTA。在实际尺寸、灰度、模糊和整页重复中不得成为灰闷暗条、沉重色块或高频暗点。不设固定明度差，真实宿主上的暗沉、层级倒置或与相邻等级近似不能由“状态可辨”覆盖。
- 状态不能只依赖普通文字同 RGB 的轻微 Alpha 差。
- 交互/选中 Tab 文字默认 `100%` 有效强度，未选 Tab 文字从 `80%` 起验证；只有原稿明确为弱提示且 1:1 仍清楚时才可降到 `60%`，不得套 `40%` muted 档。普通标签同样分别检查 `labelSurface / labelText`：忽略文字时底板仍与卡片可辨，有效信息文字不淡成水印。媒体封面内受保护标签仍按原稿零差异验收。

### Icon

- 每张卡片先用 `titlePaintInventory` 与 `iconGlyphInventory` 和全量颜色通道清单逐路径做差集：标题 TEXT 的可见 Fill、文字区间、各渐变色标、Stroke、颜色 Effect 及标题装饰；Icon 图形本体的 Vector/Boolean/IMAGE、描边、材质色标，以及独立底托。所有非保护可编辑通道都要有目标配方和新鲜读回；只改卡片底色、标题光晕或 Icon 底托而本体保留旧色，直接 FAIL。位图图形若不可安全换色须保持 `raster-blocked` 并报告，不能靠叠加假图形/按钮将其记为完成。对照 1:1 原稿与新稿，缩小整页图不能代替逐层验收。
- 所有需换肤功能 Icon 的 Fill 与 Stroke 均进入新主题，并引用或有依据地派生自 `schemeAnchorContract.icon`；稳定主体遵守 `accentFamilyPlan`，在真实底托上清楚，已有金属明暗与局部反射不塌缩。媒体/Logo/图片 Icon 与前三名受保护名次图形未改。
- Icon 容器是 `Icon 底托 < 选中 Tab < 主要按钮/CTA` 中最轻的一层，同时弱于 Icon 图形；不能直接复用 Tab 或高饱和按钮色后仅降低节点 Alpha 来伪造层级。
- 存在局部 Icon 底托时，按《颜色决策规则》第 7.1 节核对 `iconMaterialRecipe.container` 与 `iconPairPlan`：有独立颜色来源、图形/底托/卡片关系与渐变职责；图形和底托在同一真实单元中联合选择，没有以“主色加白”代替判断，也没有为追求异色任意增加新色。允许有依据的辅助色、材质色或中性色，同主色不是验收条件。
- 图形、按钮与普通辅助底托均未被全模式 S/V 锁定；第 3.2 节浅→浅基线的适用范围明确，未扩大到其他宿主或底托，也未在视觉失败时被当成硬约束；无彩源底没有因原 `S=0` 被机械映射为统一中性色或统一 V。分别检查实际底托与卡片的冷暖/色相关系、图形与底托的承托关系，不能仅凭轮廓清楚通过；确属明确锁定项或保护项的底托有职责依据。
- 实际尺寸下图形清楚，底托起到承托作用；整页重复排列的视觉权重合理，同族配方一致或变体有依据。底托可有柔和消隐边缘，不要求所有边界都强描边；同色混融或异色割裂时有针对性的试色修正。原渐变结构与透明度规则未因模仿参考而突破，前三名底托仍完全保留原 UI 配色。
- 多层 Icon 保留可感知明暗层次及原高光位置、方向和覆盖范围，仅在第 3.2 节浅→浅基线真实通过并决定沿用，或明确通道锁定适用时保持原 S/V，其他情况不锁定数值跨度；不同 Paint 没有被写成相同渐变或相近暗色。
- 原稿所有功能 Icon 的可见渐变（不限金属）在代表试色与最终全实例上执行 `scripts/material_stop_audit.py`；原有不同 RGB 或饱和度职责的色标塌缩为同一 RGB/同一 S 关系时，`iconMaterialAudit=FAIL → Phase 3/5/6`，先修色标角色并重新查看原生尺寸。无塌缩只通过这项确定性检查，仍须由真实截图证明受光面、镜面带和暗端可感知；不能把脚本 PASS 当作材质 PASS。
- 实际尺寸下受光面、阴影、高光各自可感知；没有以层数相同或少量亮边代替材质成立的证据。参考图片的立体效果未被误报为目标矢量 Icon 已实现的效果。
- Icon 图形与容器、文字、按钮清楚区分，没有发闷、过深、材质消失或重复抢焦点；同一 1:1 截图明确排除了 `gradient-stop-collapse / container-too-heavy / pair-low-separation / pair-over-salient`。
- `targetUiMode=light` 时，普通功能 Icon 底托须淡淡带有一层协调颜色，并明显弱于选中 Tab；但低强调不等于不可见，在 1:1 下临时忽略图形时，底托轮廓/表面仍须与卡片分离。实际尺寸、灰度、模糊和整页重复中不得暗沉、形成沉重色块或高频暗点，也不得融入卡片像缺少底托。不设固定明度差；底托过暗、过淡消失、接近 Tab 强度或因高频重复累计压过 Tab，均不能用“弱于按钮”或“图形还能看清”放行。
- Icon 与按钮按《颜色决策规则》第 3.2–3.2.1 节分别核对已记录的目标 UI、KV 明暗与色彩力度、实际宿主和鲜亮/干净深色方向，检查来源与角色依据。按钮执行按钮主体门禁；普通鲜亮 Icon 的稳定主体可为 `B=100`，不得仅凭 B 判过亮。Figma H/S/B 读回应符合 `iconPairPlan`，且原本不同的可见渐变色标在目标中仍有可感知 RGB 或 S/B 差异；使用浅→浅基线时逐色标核对其原 S/B/Alpha，仅当该基线真实通过且护栏不失败时才可沿用，偏离时记录必要调整理由；其他明确锁定项与原稿保持。各级 Alpha、混合模式、渐变空间结构及保护项按对应规则核对。原稿/新稿同尺寸真实场景中，主体、暗部、高光仍可区分，图形清楚、操作醒目；机械压低鲜亮色造成灰闷暗块或不同色标截断同色均失败。加深或提亮本身不构成失败；不能用通道保持、层数相同或少量亮边代替实际显著性。

### 小按钮与 CTA

- 当前可用的全局 CTA 是最强操作焦点；大小主要按钮的共同操作色必须强于选中 Tab，选中 Tab 又强于普通 Icon 底托。CTA 与小按钮主体共用 `buttonPrimary`，CTA 的进一步强化来自原有尺寸与材质。按实际背景的 1:1 和整页缩略图检查整个按钮主体；主体与 Tab/底托近似时不能仅因字可读或按钮尺寸大而通过。
- 小按钮与 CTA 的稳定主体共同引用 `schemeAnchorContract.button`，代表色、主体色相和中间调一致；Paint Recipe 只因原有材质层结构不同而派生暗部、高光和反射。出现黄/橙或其他可见异色分裂即 FAIL，CTA 的强化由尺寸与原有材质表达，而不是另选按钮色。独立可编辑 CTA 即使嵌套在营销 Banner 内也必须进入覆盖；只有已烘焙进不可编辑单图或用户明确要求整 Banner 含控件保持原样时才可排除。
- 若使用金属矩阵，`metalAccentEvidence` 的来源区域、金属家族和稳定明暗关系必须与 `metallic-analogous` 配方逐项对应；`gold-bright` 是独立的正常明亮金色对照，检查其金黄色相、感知明度、有效彩度和受光面积，不要求 KV 已含金色像素，但禁止暗铜/棕橙/土黄替代，并核对其默认深棕按钮字；`clean-deep` 单独证明来源、彩度与受光，不得为了白字或对比度任意压成灰黑。
- 特别鲜艳的无金属撞色小按钮与 CTA 若标为 `vivid-contrast-white`，共同优先使用纯白/近白文字方向，并须各有真实文字覆盖区的白字 1:1 试色。白字在真实文字覆盖区对比度不足时再试深色字，并依据可读性、`buttonPrimary`、明快感和材质效果选择；缺白字失败证据或仅深字静态比值更高均直接 FAIL。其他主要按钮的文字方向按实际材质、宿主和可读性确定，同一家族小/大按钮仍检查一致性，不套白字默认。`gold-bright` 默认共同使用深棕字；若未验证深棕，或为保白字将金色压暗，直接 FAIL。禁用、次级和明确浅底按钮按已登记角色验收。
- 每个明确禁用按钮都有正常态映射，Fill、Stroke、Effect、文字色与正常态配方相同；唯一默认状态差异是最小完整按钮视觉单元相对正常态 `50%` 的整体有效透明度。另选灰/米/低彩 RGB、只把文字或底板单独变淡、或在已有 50% 衰减上再次乘 0.5，均 FAIL。记录 `disabledButtonOpacityAudit` 的正常/禁用根、实际有效倍率与防重复计算证据。
- 非操作色块的面积和重复频率没有形成更强累计视觉重量。
- 按钮没有与背景融为一体，未出现无光照依据的多色扩散、亮框吞没主体、与 KV 无关的大面积高饱和块等实际问题。不能仅因明亮、邻近色过渡或强高光而判“廉价/过艳”，也不能用降低饱和度或压暗全体角色作为默认修正。

逐项执行《颜色决策规则》第 8.1 节，生成 `finalAudit.buttonCompositeAudit`：

- 实际合成后的基底达到符合 KV、目标 UI 模式和操作角色的足够彩度与明暗力度，并有按钮主体、局部背景及邻近弱控件的代表区域证据；高光、反射没有把主体颜色冲成大面积灰白/奶油色而削弱焦点。局部亮边和自然反光不因颜色浅而自动失败；浅色 UI 若使用 `clean-deep` 主要操作，须有 KV 主体/标题/金属来源、比明亮候选更清楚的宿主分离及保留彩度/受光的证据，不能用低彩灰黑代替。
- 主要按钮相对真实页面/卡片背景有清楚的明度、彩度、色相或轮廓差异；在 1:1 与缩略图中都能辨认为当前操作，启用态与已有禁用态明显区分。
- 基底、高光、环境反射各有职责和可见差异；不能只因为保留了渐变层数或文字对比度合格就通过。
- 主体明度与受光感符合已记录的 KV 光照气质；既检查泛白失色，也检查压暗基底/反射造成的沉重。高光实际覆盖面积与有效贡献有截图证据，不以单一 Alpha 高低判好坏；不能为提高白字对比度而牺牲明快感后仍判视觉通过。
- 若有 `buttonMaterialAlphaOverrides`，按《颜色决策规则》第 8.1 节逐通道核对既有 Fill/Stroke/颜色 Effect 的材质强度差异及因果证据；原透明色标/关闭层未激活，原可见层未归零，基底不透明性、蒙版、节点/祖先 Alpha、几何和全部保护区未改变。
- 按《叠层合成审计》核对每个按钮的完整材质根、实际层级、蒙版作用范围与祖先/状态贡献；主体分区和面积证据不由局部亮边代替。用户明确要求明亮鲜明按钮时，暗沉版本不能以高饱和或深色风格理由通过。孤立白画布截图不等于真实深色宿主已验证。
- 浅色 UI 配淡色 KV 时，核对配方是否有来源，并在真实宿主上比较明亮有彩与有证据的干净深色方向：默认使用同一主体/标题/金属家族中的更深中间调，例如淡黄背景配深棕；只有明亮按钮在浅表面上仍能清楚突出时才保留明亮方向，且不得把任意颜色压成灰黑。深色 UI 的深色方案同样按清晰度和材质验证，不以低 V 本身判失败。出现发灰、泛白、不合时宜的暗沉、与弱标签/禁用态近似或主要操作不突出时，必须有真实试色修正记录；仅提供一段“协调/克制/饱满”的理由不得判 PASS。所有色相按同一角色标准验收。

任一失败，`FAIL → Phase 3/5/6`。

## 7. 卡片氛围与材质

- 氛围只使用 `cardAtmospherePalette` 的环境色及邻近色；不含标题、人物、箭头、Logo、金属包边、按钮色或局部反光。
- 氛围位置符合《颜色决策规则》第 5 节的默认锚点或有依据的原空间家族；不为套位置规则移动图层。
- 先核对浅色撞色方案的 `cardSurfaceStrategy`：`tinted-near-white` 的稳定底明显降低 S 并提高明度，`pure-white-atmosphere` 的稳定底为纯白且主题色只留在原有顶部氛围/Chrome；页面↔卡片边界仍清楚，卡片没有因主题染色显脏。再按《颜色决策规则》第 5 节矩阵逐卡核对实际 `themeTransition`、稳定底色与完整氛围叠层：`light-to-dark` 有可感知局部有色受光，不能是白灰雾或暗块；`dark-to-light` 的每个旧光影/形状都有 `keep/fade/remove-visually` 结论，干净浅底上只保留必要的极淡环境光。冗余纯装饰氛围可通过既有 Paint/色标 Alpha=0 视觉移除，但节点、几何、蒙版和稳定底色不变；若仍在卡顶形成暗了一块、灰带、厚重光斑或高频形状，直接 FAIL。同模式保持空间配方，已登记材质强度例外逐项核对。
- `targetUiMode=light` 的无彩暗层审计已覆盖 `#000000`、近黑灰、低明度中性色、暗色 Effect、低明度渐变端点与主题装饰 IMAGE，并区分结构蒙版/Boolean 几何和真实输出。卡顶氛围不得出现大片黑灰、深纹理或只因 Alpha 低而放行；Icon/按钮的主体、中间调与大面积塑形暗部也不得形成低明度脏块。
- 既有 SOLID 模糊光斑、GRADIENT、位图/滤镜、反射、底色羽化层都已分类；没有氛围的卡不凭想象新增氛围。ALPHA 蒙版灰色与 Boolean 操作数未误判为灰色表面，结构蒙版未改动。
- 多层在同一区域重叠后仍保持干净光色，不能凭单层饱和度、低 Alpha 或两种相邻 Hue 直接通过；核对最终主体/受光区、向稳定底色消隐及邻近按钮关系，不能只有一个鲜亮像素或一条亮边。
- 原稿卡顶若由两个或多个可见氛围圆/光斑/层共同形成，逐成员核对 `materialRelationPlan`：同属 `cardAtmospherePalette` 只要求同家族，不要求同 RGB；原有冷暖、色相、彩度、明度或空间受光差异不得被压成一个颜色。计划快照、代表读回和最终读回的 `scripts/material_relation_audit.py` 均通过，且 1:1 下各层仍承担可解释的不同光照职责。
- 普通卡片标题默认使用 `textBaseColor`，通过原字号、字重和位置建立层级；仅登记了原稿强调或明确业务/主题证据时才使用 `titleAccent`。标题是稳定纯色或窄差渐变，只在边角有小范围受光，不与氛围、Icon、按钮共享大渐变，也不机械复用 `dataAccent` 或金色按钮。
- 标题若原有多个可见 Fill、文字区间、渐变色标、Stroke 或颜色 Effect，`textBaseColor/titleAccent` 只绑定稳定代表 Paint；其余成员按 `materialRelationPlan` 保留克制但可感知的职责差异。所有标题通道变成同一 RGB，即使 Gradient 类型、色标数和位置未变也直接 FAIL。
- 卡片顶部包边、角饰、标题装饰线和顶部光带引用表面/`cardAtmospherePalette` 家族，未机械复用 `dataAccent`、Icon 或 `buttonPrimary`。重复卡顶出现黄色/金色边圈而无原稿业务强调与新主题证据时直接 FAIL。
- 深色方向性描边只用于规则允许的角色和转换，方向与 KV 光源一致；重复普通卡和内部异形层没有机械白框。
- 原稿已有金属/玻璃层次没有因换肤被压平；材质没有机械指定色相。

以上记入 `finalAudit.cardAtmosphereAudit`，包含逐卡覆盖、实际模式、层职责、合成截图和修正记录。任何与新表面家族冲突的旧主题氛围即使低 Alpha 仍可见，也视为残留。失败时 `FAIL → Phase 3/5/6`，规则校验不得替代真实跨模式试色。

## 8. 媒体、前三名、营销 Banner 颜色保护和实例

- `protected-media-overlay` 的 Fill、Stroke、文字色、Paint/节点 Alpha、blendMode、mask 和 Effect 与原稿完全一致。
- 保护范围精确到封面内左上/左下标签、播放量及图标，不以媒体组件祖先整体排除。
- 封面外标题、副文案、普通标签和交互信息已换色并进入残留扫描。
- 按 `sourceAudit.protectedRankTop3` 与副本映射逐项核对前三名名次文字、奖牌/徽章、底托/领奖台和附属形状。Fill、Stroke、所有渐变色标/Alpha、多色 Vector region、Effect、相关图片参数及节点 Alpha/blendMode/mask 与原稿一致；不能只核对主色或数字。
- 保护项与代表/扩展写色集合按节点及属性/文字区间/Vector region 核对，无保护通道被覆盖；混合节点允许只写非保护通道。若有误改恢复，`protectedColorRestorations` 有原稿指纹和恢复后零差异证据。解绑后保护映射仍有效，无通过祖先 Alpha/滤镜/覆盖层间接改色。
- 前三名姓名、收益、榜单标题、外卡片、Tab 与第四名起的普通编号未因混合父级而被整组跳过。合法外背景变化造成透明边缘的合成变化不视为 Paint 修改，也不能以此为由改保护色。
- 按 `sourceAudit.protectedMarketingBanners` 逐个核对实际受保护的创意背景、插画、图片和营销文案通道，与原稿零差异且未进入残留清理；同时核对显式排除的独立 CTA/操作控件已按交互家族换肤，未因祖先保护、实例嵌套或 Banner 名称漏改。普通业务卡片未被误保护；只有烘焙单图或用户明确要求整体保留时才允许整棵零差异。
- 只有计划内副本实例被解绑；解绑前后可见结构、尺寸、位置、顺序、文案和素材一致。
- 剩余换肤相关实例具有所有应换肤 Paint/状态已本地覆盖、保护 Paint 未改的证据，否则按需解绑；不要求受保护名次/形状进入新色板。

将前三名结果单列为 `finalAudit.protectedRankTop3Audit`，营销 Banner 结果单列为 `finalAudit.protectedMarketingBannerAudit`；后者包含实际保护集合、排除的 CTA/控件、源/副本节点映射、保护通道比对、控件目标配方及 1:1 截图。不存在时记录 `not-applicable` 与读取证据，不虚构保护节点。

失败时 `FAIL → Phase 1/6`。

## 9. 全 Paint 与渲染残留色

先用**副本目标 Frame 的 Selection colors 或等价的全子树颜色聚合**做快速残留预筛；遍历遇到 `kvLockedSubtreeRootIds` 必须停止下钻，新 KV 原色不计为旧 UI 残留：按颜色列出 Fill、Stroke、渐变色标、带色 Effect 及文字区间的贡献节点/通道，并标记可见性、有效 Alpha、所在视觉单元和精确保护类别。逐一定位旧 UI 色在实际画面中的贡献，优先修正可编辑、非保护的残留；改后重新聚合受影响区域并取 1:1 截图。Selection colors 是候选索引，不等于渲染结果或保护判定：它可能列出被遮挡/极低 Alpha 的 Paint，也不解析 IMAGE 内部像素。不得因为颜色相同就批量覆盖内容素材、品牌色、前三名或营销创意。预筛结果和处理/排除理由进入 `finalAudit.residualColorAudit`，随后仍执行下列完整双层审计。

第一层遍历副本 UI 范围所有可见 Fill、Stroke、渐变色标、Effect 和低 Alpha 装饰，排除 KV 锁定子树；IMAGE Paint 使用既有分类，不得统一排除。

第二层检查整页和关键局部截图的实际像素，重点看：圆角/边缘细线、标题装饰、状态底色、异形容器、Icon 内部、KV 接缝和主题装饰位图。

只排除：精确 `protected-hero-controls` 功能叠层、精确媒体保护区、已核实的 `protected-rank-top3` 名次与形状配色、已核实的 `protected-marketing-banner` 完整子树、品牌专属色、真实成功/警告/错误/危险语义色，以及不可编辑内容媒体内部像素。前三名和独立营销 Banner 的各种原有颜色均按原稿保留，不作为残留清除，也不用于扩展新主题色板。排行榜保护范围之外的内容、第四名起的普通编号和其他普通装饰仍参与残留扫描；普通业务卡片也不能被营销 Banner 规则整块跳过。

任何不属于新方案或上述排除项的旧 Hue，必须定位贡献节点并处理。已纳入角色色板并有依据的 Icon 底托辅助色、材质色及中性色，不因不同于环境主色就判为残留；不得在残留清理时统一刷回主色。属性扫描通过但截图仍可见旧主题色，同样 `FAIL → Phase 6`。

## 10. 五种视觉视图

必须查看：

1. 原稿和副本整页彩色图。
2. KV→首卡衔接及关键区域 1:1 图。
3. 灰度图：检查明度拓扑。
4. 轻度模糊/眯眼图：检查面积和重复频率。
5. 缩略图：检查第一视觉焦点。

关键区域覆盖实际存在的收益复合卡、KV 衔接/认证文字、卡片标题＋氛围＋Icon＋小按钮、一级/二级 Tab、媒体覆盖层、前三名保护区、独立营销 Banner 和 CTA；缺失角色带读取证据记不适用，不要求补造角色或截图。五种视图仍须覆盖真实结果，可从同一有效截图派生灰度/模糊/缩略图；不重复生成未变化的原稿视图。

必须主动判断：

- 页面实际重量是否符合 `targetSurfaceDepth`，未被主体高光漂白或边缘暗部压黑。
- 页面、卡片、容器层级清楚，且与 KV 稳定环境属于同一视觉世界；浅色撞色方案的卡片足够接近白色，未被不必要的高 S 主题底色染脏。
- 全局/局部第一焦点符合 `targetSalienceOrder`。
- 页面达到 `colorClarityPlan` 的实际彩度、明度、受光感与对比度目标：主题色彩有力度、视觉重量符合 KV、各层清楚、主要操作突出、状态可辨；按钮合成后主体颜色与材质层次成立，整页关系美观协调。
- 标题、Icon、Tab、小按钮和 CTA 各有独立角色，没有共享同一渐变；Icon 图形与底托成组后没有底托偏重、渐变塌缩成纯色或整页重复抢焦点；普通 Icon 底托、选中 Tab、主要按钮/CTA 的颜色显著性依次增强，没有倒置或挤成同一等级。
- 整页没有旧主题残色、廉价材质、多色扩散、透明叠层 Bug 或明显审美冲突。

任一视图失败都不能用数值合格覆盖；返回对应阶段修正。
