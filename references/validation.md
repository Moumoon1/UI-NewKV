# 验收规则

Phase 3 冻结适用规则时读取检查分类与第 11 节闸门清单；Phase 7 读取全部适用检查。本文件定义检查方法、PASS/FAIL、带证据的警告和回退阶段；可在授权范围内解决的问题必须在同一副本自动修正并重新验收，不向用户索要方案选择。

启用 `style-adaptation` 时，结构、Paint 存在性、素材和原材质保持检查只对[《画风迁移规则》](style-adaptation.md)中逐项登记的外观差异适用例外，转由 `styleAdaptationAudit` 验收。其他节点与所有业务/精确保护规则不变。

## 1. 执行链真实性

核对 `executionPhaseLog` 和真实写入集合：

```text
inspect → kv-style-check → kv-analysis → preflight → clone-and-kv
→ representative-trial → trial-review(pass)
→ expand → audit
```

必须先按[《执行工具》第 5 节](execution-workflow.md#5-执行覆盖严格验收与性能)核对冻结规则、全量颜色清单和完成目标，再证明：

- `kvStyleComparison` 在配色方案与任何写入前完成，包含新旧 KV 的画风差异证据及原 UI 冲突检查；模式不是仅由颜色、IP 更换或深浅变化触发。

- `preflightThemeDecision=pass` 早于首次 UI 写色。
- `requestedUiMode` 和 `targetUiModeSource` 与用户要求一致；指定深／浅色时，最终主要 UI 表面实际呈现该模式，不能只改字段或被 KV 推断覆盖。`sourceUiMode` 有原稿证据，`themeTransition` 由原稿与最终目标模式计算，相关 Icon／按钮及氛围规则使用同一模式；未指定时有自动判断依据。
- `representativeNodeIds` 早于代表试色产生。
- `representativeCoverage` 覆盖全部非等价按钮/氛围材质、状态及需要不同方案的背景；全页实际实例清单与最终上下文核对数量一致，不能只验一类代表。
- `representativeMutatedNodeIds` 只包含完整场景的白名单、必要后代及预登记共享背景通道；只读依赖不等于写权限。
- `trialGates` 有各场景真实上下文的 1:1、灰度、模糊和缩略图证据，整页图只作上下文检查；未扩展旧皮肤不在 Phase 5 冒充整页残留或美观 FAIL/PASS。
- 按[《局部试色与执行工具》](execution-workflow.md)第 2 节核对每批扩展对应的配方/依赖/映射指纹，门禁在该次写入前有效；历史 `trialGateStatus=pass` 不独立构成凭证。共享依赖变化后的相关实例均已更新和重验，无过期门禁。
- `expansionMutatedNodeIds` 来自后续独立写入调用。
- `buttonCompositeReview` 中声称已试色的版本均有同一副本、同一代表白名单的实际写入与截图记录；修正或比较结束后实际 Paint 对应最终选中版本。

任何事后补记、代表试色和全页扩展同调用、白名单外写入、过期门禁或缺少证据均为 `FAIL → Phase 4/5`。合法恢复/局部回退应追加实际事件并重验受影响依赖，不要求重做 clone。批次异常有新鲜读回和完成/待写/冲突分类，无未解决冲突；属性工具通过不能替代视觉通过。

## 2. 原稿与副本结构

用稳定 ID 重读原稿并与 `sourceAudit` 比较。原稿的父级、位置、尺寸、结构、文字、字体、素材、Paint、Effect、样式、变量、组件和旧 KV 必须完全不变。

快照/差异检查复用《局部试色与执行工具》第 4 节脚本；原稿策略不允许任何差异，副本只接受事先登记的确切前后值。保护检查优先于允许差异，采集错误、节点缺失、映射不完整不能被忽略。脚本未覆盖的特殊属性另取证；不从实际错误结果反推白名单。

按原稿→副本既有节点映射和子节点相对顺序比较副本；无新增节点时可直接比较索引路径。只允许：

```text
复制产生的新 ID
副本根 x
指定 KV IMAGE Paint 内容
kvFitPlan 白名单内的 KV IMAGE scaleMode/imageTransform 与专用载体 x/y/width/height
kvFitPlan 内最多一个绝对定位主图载体、一个环境补底节点或 Fill
启用独立主图载体后指定旧 KV Paint Alpha=0
mutationPlan 内颜色和 Paint Alpha
按《文字换色与恢复》逐项登记的普通 TEXT 自身 Alpha 覆盖（非状态/祖先/保护）
已登记的按钮材质 Fill/Stroke Paint opacity 或已有颜色 Effect Alpha 覆盖（保持原有效开关及不透明基底）
规则允许的跨模式 card.atmosphere 配方
light-to-dark 计划内 1px INSIDE 方向性描边
light-to-dark 收益卡最多一个底部氛围 Fill
有记录的实例本地覆盖与副本实例解绑
有证据的本次解绑新增、源实例不存在且隐藏无业务节点的结构恢复移除
有证据的 kv-asset-subtree 节点整体 Alpha=0
有记录的 theme-decoration-raster 滤镜/Paint Alpha
跨深浅模式 heroControlAdaptations 精确前景通道与必要的既有底托颜色/Paint opacity
```

每项 KV 例外必须逐节点/属性核对 `kvFitPlan.allowedMutations` 的前后值；新增节点只影响登记过的 KV 层，既有 UI 相对顺序不变。普通 TEXT Alpha 例外另逐项核对状态、保护区间、有效强度及字体/文案/几何零差异，不能豁免祖先或整个子树。其他几何、布局、圆角、裁切、层级、顺序、混合模式、节点整体 Alpha、文案、字体、非 KV 素材、矢量/布尔/蒙版、共享样式/变量和主组件必须一致。矢量区域 Paint 与拓扑分开比较，允许的换色不误报成几何变化；原稿仍核对全部属性。不得因索引变化跳过 Hero 子树或原稿完整性审计。

逐项核对 `detachedInstances[].structureRecovery`：移除集合只包含有完整证据的本次解绑额外隐藏无业务节点，原有/有业务节点未删除；恢复后的数量和既有相对顺序与源实例一致，节点映射及受影响白名单已重新建立，解绑后的操作没有直接使用旧索引。旧 KV 标题/Logo 隐藏结果与截图逐项一致，不得以隐藏节点不参与渲染为由略过索引变化。任何误删、漏映射或沿用失效白名单为 `FAIL → Phase 4/6`，先恢复结构和映射再继续写入。

复合异形卡逐层比较 Z 顺序、节点/Paint Alpha、blendMode、mask 和可见轮廓。结构表面 Alpha 保持；已登记材质 Paint 强度差异逐通道验收，不误作结构变化豁免整个子树。出现后层透出、双影、接缝、脏边或前层半透明 Bug，`FAIL → Phase 6`。

## 3. KV 与图像

- 副本实际显示用户的新 KV，原稿仍显示旧 KV。
- `directFitCheck` 证明先检查了原尺寸/同宽使用；本可直接放入却人为缩小、为导航预留整圈边距，或随后补画构图，均为 FAIL。真实裁切导致的必要等比适配应有边界与截图证据。
- Hero 外框位置、尺寸、裁切、圆角、Auto Layout 占位及下方 UI 起点不变；图片适配策略和 KV 专属载体只按白名单变更。
- 默认保留原 KV 设计尺寸或页面同宽尺度，宽高比正确，允许超高部分仅从下方截去；不能为了完整显示尾部而整体缩小。记录实际可见/截去区域及标题、Logo、主体是否可见，关键内容意外被切须修正定位并复验。只有用户明确要求完整显示时，contain 分支要求整图四边完整。
- 实际截图确认主图经过全部祖先 clip/蒙版后符合已登记的尺度与下方裁切策略；contain 分支仍须整图完整；只设置 `FIT`、只检查节点边界或只比较 imageHash 均不足以通过。
- contain 留白/透明处没有旧图透出；必要环境补底来自新 KV 稳定环境色，位于主图后方且不越出 Hero，没有重复标题/主体或新造内容。无留白则无需补底。
- `protected-hero-controls` 按真实 `themeTransition` 逐节点核对：同模式全部样式精确保留；跨模式仅《Figma 执行规范》第 5.4 节预登记的前景及必要底托通道可适配，读回校验目标值及必要性证据。未登记样式、几何、字体、文案、素材、状态、节点/祖先 Alpha 保持，不新增底板或间接覆盖。实际新 KV 宿主上的可辨性与第 5.1 节适用的对比度策略仍必验；跨模式不机械追平原稿比值。记为 `protectedHeroControlsAudit`，不存在时带证据记不适用。
- `kv-asset-subtree` 仅隐藏已经烘焙进新 KV 的旧视觉资产；倒计时、规则、状态、导航等 `hero-adjacent-ui` 仍可见可读。
- 每个 IMAGE Paint 已分类；内容、品牌素材与未知图片哈希未改变。

将上述结果记为 `finalAudit.kvFitAudit`。仅用户明确要求完整显示时，任何比例均可使用 contain；比例差异、留白或低源分辨率本身不判失败，源清晰度如实记录。只替换 imageHash 但截图仍显示旧 KV、存在非计划的祖先裁切、功能 UI 被遮挡/位移，或误改内容图片，`FAIL → Phase 4/6`，在同一副本自动修正适配，不因重设裁切/定位请求审批。

## 4. Paint 与视觉承载层

逐个检查 `visualSurfaceCarrierMap`：

- 需要换肤的卡片、容器、Tab、标签和按钮实际 Rectangle/Vector/Boolean/Ellipse/Frame 已进入目标色板；媒体与前三名颜色保护项须与原稿一致，不要求进入目标色板。
- 没有只改语义父 Frame 而漏掉异形承载层。
- 没有给 UI 空外层或更大无圆角兄弟节点新增 Fill，造成方形底、圆角丢失或边界扩大；已登记的 Hero KV 环境补底单独按第 3 节验收。
- 多层表面的 base、shadow、highlight、stroke、state-indicator 和 decoration 职责保持清楚。

同模式换肤逐节点比较 `paintPresenceMask`：除 `kvFitPlan` 逐项登记的 KV 例外和已确认的旧 `kv-asset-subtree` 外，Fill/Stroke/颜色 Effect 的存在、可见性、有效 Alpha 开关、Paint/Effect 类型、数量和顺序必须一致。原空通道仍为空，零贡献 Paint 未激活，可见 Paint 未删除/归零。UI 氛围渐变类型、方向、范围、色标数量和位置不变。

跨模式差异必须只出现在计划内节点并符合对应氛围矩阵。任何承载层漏改或无授权新增 Paint，`FAIL → Phase 1/6`。

## 5. 文字与对比度

对比度使用最终显示 RGB 和逐层合成背景：

```text
contrast = (L1 + 0.05) / (L2 + 0.05)
```

必须包含文字 Paint Alpha、文字节点/祖先 Alpha、表面 Paint Alpha、渐变最差点和下层背景。RGB 先转线性 sRGB 再计算相对亮度 L；图片或复杂渐变使用 1:1 截图采样最亮和最暗代表点。Paint 颜色、有效显示颜色和抗锯齿边缘不能混为一谈。

Phase 3 冻结 `contrastPolicy=source-baseline/contextual` 与 sourceUiMode、targetUiMode、adaptationMode 及理由。深→深、浅→浅且不涉及画风迁移时使用 `source-baseline`，真实可辨性与“不低于原稿对应对比度”同时必验；深浅转换或画风迁移使用 `contextual`，按新 KV、真实宿主、材质和角色确定目标，记录源/新比值但不以数值回退本身判失败。`4.5:1`、`3:1`、`7:1` 等 WCAG 固定数值仍仅作参考；用户明确要求 WCAG 或具体比值时另外记录 `contrastStandard=strict-standard`，两种策略都同时执行指定要求，不隐含要求 contextual 达到原稿极高比值。颜色可以根据 KV 调整，跨深浅可反转明暗方向；比较的是最终显示关系的比值，不是锁定旧 RGB、HSV V 或绝对亮度。

- 普通文字、规则、必读信息及小号说明须在实际尺寸、真实背景上清楚可读，正文强弱层级明确；不能只因比值低于参考值判失败，也不能仅凭比值高认定清楚。
- 金额、任务/作品中已确认的 `data.emphasis` 区间与顶部收益强调数据须鲜明、突出、清晰，不为追求参考数值压成灰闷深色。小号单位/说明与主数字分开判断，不把整段正文都升级为强调数字。
- 按钮文字与按角色选定的鲜亮或干净深色主体联合验收，同时检查渐变最亮端、最暗端和半透明合成点是否处于实际文字覆盖范围。远离字形的装饰亮边不充当文字背景，穿过文字的亮带不能遗漏。采样记录须包含坐标、对应文字节点及背景合成依据；不得把抗锯齿文字边缘误当作背景。
- KV 衔接文字、认证/状态、每种正文层级、Tab 和按钮文字分别抽检真实节点。
- 按钮浅色/深色文字都经过组合比较，最终方向有 KV、材质、显著性和审美证据，不是固定纯白/纯黑或单一最高数值。

数值参考来自 [W3C WCAG 对比度最低要求](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)。默认换肤不等同于 WCAG 合规验收。`strict-standard` 中依据用户要求判断字号、实际显示缩放、字重及真实语义豁免；不能把普通说明标成装饰来豁免，也不能用视觉通过冒充标准达标。精确保护文字保持原稿 Paint，必要冲突如实披露，不授权改保护色。

`textRampIntegrity`：普通文字默认共享 `textBaseColor`，`100/80/60/40` 仅为有效强度的起点，不重复乘入原节点弱化。真实背景需要的 Alpha/局部 RGB 差异分别登记 `textRampOverride` / `textBaseColorOverride`；普通 TEXT 自身 opacity 按 `textNodeAlphaOverrides` 逐项验收。层级必须真实清楚，但不能只因次级文字为 100% 就判失败；有依据的局部高 Alpha 不等于全页无差别拉满。按钮、链接、语义状态、标题和关键数据按独立角色验收；精确保护文字不套用新阶梯。

### 可读性修正与约束

文字实际难读时，确认限制来自 TEXT 自身、Paint 还是结构/状态祖先，按《文字换色与恢复》联合调整合法的文字方向、有效强度、背景与材质。40% 普通 TEXT 自身只是文字强弱时可使用最小 Alpha 覆盖；已清楚可读的文字不为跨过参考比值强行提高 Alpha 或压暗按钮。

`contrastAudit` 始终核验真实可辨性；source-baseline 另核验原稿基线，低于原稿对应比值即 FAIL；contextual 按冻结的情境目标、角色层级与已明确数值要求验收，不把原稿比值作为默认下限。未达到未指定的 WCAG 参考值本身不产生 FAIL；若记录了与标准的比较，须如实标明仅为参考及未满足的标准。结构/保护约束登记具体节点和实际影响；可读性、按钮显著性与材质或氛围干净度的真实失败仍须修正，不能以数值不再硬性要求为由放行。

`strict-standard` 下未达用户明确要求的节点不能通过警告豁免；保护/结构冲突须具体说明并请求必要选择，不改字体/布局兜底。只有启用标准验收时才记录各节点 `standardStatus=met/not-met/exempt` 及依据；默认模式不声称整页 WCAG 合规。

字体加载错误本身不属于对比度/文字完整性失败；以《文字换色与恢复》的实际颜色写入、读回、字体/内容/几何和截图证据判断。纯颜色路径未尝试或实际颜色未改不能算完成。

真实可读/可辨性失败、source-baseline 下对应合成对比度低于原稿，或 `strict-standard` 下未达用户明确要求时，`FAIL → Phase 3/5/6`；联合调整背景与文字，不得通过改字号、字重或布局兜底。默认模式禁止仅因未到 `4.5:1` 等参考比值触发回退或中止。

### 5.1 原稿对比度基线与可辨性

Phase 1 在 `sourceAudit.contrastRelationships` 建立实际存在的对应关系；Phase 3 将 ID、类型、节点范围与采样职责冻结进 `contrast-baseline` 机器规则的 verifier。覆盖文字/关键数据对宿主、页面/卡片/内部容器之间、Tab 选中与未选中表面、指示条对底色、功能 Icon 图形对底托、按钮/CTA 主体对宿主及标签对主体。精确保护对象仍保留原值，但其真实宿主变化也需核查并如实记录冲突。装饰高光与材料内部塑形色标不逐个升级为业务对比关系；实际不存在或无可见边界的关系在预检附读取依据，不在验收时删掉失败关系。

每个关系按实际材质/状态/宿主选择最少完整代表，登记全部实例→代表映射；非等价上下文分别比较，最终逐实例核对。记录相同角色、相同采样职责的源/新合成颜色与未四舍五入的比值。纯色 NORMAL 叠层可由快照中真实 RGB(A)、Paint/节点/祖先 Alpha 自下而上计算，不能漏掉宿主或重复乘 Alpha；复杂渐变、混合、IMAGE 和氛围采用真实 1:1 截图，保存坐标、像素比例、哈希与取样依据，排除字形边缘/抗锯齿。文字可用完整 Paint 与真实背景计算，不能从细字的抗锯齿像素推算全文颜色。

可辨性分别进入 `readability/surface-discernibility/state-discernibility` 的冻结视觉检查，逐实例范围独立覆盖，不能用一项的 PASS 代替另一项。

对比度只表示差异大小，不表示强调顺序。原稿中确实可比较、共享同一实际背景与采样职责的强弱关系，另建 `emphasisOrders`（格式见执行工具第 4.7 节）：比较强成员/弱成员各自对宿主的对比度之比，新稿须仍大于 1；仅 source-baseline 另要求不低于原稿的相对力度。适用的比值门槛与相对强弱不倒置同时通过，不能互相替代。不能把不同宿主、不同职责、窄装饰亮边或整个 CTA 的业务权重硬塞为同背景比值；多信号状态和材料层次仍以完整视觉单元验收。原稿没有该种顺序时不虚构数值约束，但不豁免真实状态层级。

同模式通常延续原稿的表面/材质明暗分工；跨模式或有依据的目标配方可以调整明暗方向，写入前明确作用与范围。高光仍承担受光、暗部仍承担塑形，选中信号与操作优先级不能倒置。原稿同色/接近的同族卡片仍延续相近基础表面，收益卡的光影差异不自动成为强反差深色底板。不能统一要求所有选中态变深或所有按钮变亮。

在覆盖文字的最亮/最暗背景、主体稳定区、边界附近与不同非等价背景中登记必要采样；source-baseline 下每个可比较样本均须满足 `newContrast >= sourceContrast`，不取平均、不删最差点、不用某处增强抵消别处减弱；contextual 下保留完整样本与源/新比值，验证目标宿主上的可读性、层级、材质和已冻结的明确数值下限，不因比值低于原稿单独回退。源/新原生截图量化口径一致，预留小幅余量后读回复算；仅容许计算浮点误差，不以四舍五入相等放行。跨模式原稿比值用于分析同一角色关系，允许前景/背景明暗方向反转，不要求追平旧极端值。系统状态栏时间/信号/电量作为独立覆盖角色：跨模式优先比较适合真实 KV 的深/浅前景，保持布局与内容，检查实际尺寸可读；不默认追赶原稿接近 21:1 的比值或新增底板。

同时独立验收：文字清楚、操作突出、状态可辨、容器范围可辨。source-baseline 下原稿比值很低时，不低于它只是必要条件；新稿仍看不清则 FAIL。仅换 H / 保留 S/V 与这条要求冲突时，联合调整合法的前景/背景，并记录覆盖依据、保持透明度/几何/材质/保护边界，使受影响门禁失效后复验。不要全页无差别压暗、增艳或新增描边兜底。

复用《执行工具》第 4.7 节严格重算，将结果写入 `finalAudit.contrastAudit`；任何缺关系/样本、过期快照、不可确定背景、违反适用数值要求或视觉不可辨均不能记 PASS。原稿保护或结构与要求确实冲突时保留证据、报告未完成，不能用警告豁免，也不擅自修改保护。

### 关系验收不得自证

最终关系复查回到原稿/新稿截图与用户规则，不把色板、已执行计划或此前 PASS 作为正确性的依据。至少核查实际存在的三类反证：

- 同族主要小按钮与 CTA 并排看彩色及灰度主体，是否一个明显重深、另一个轻浅，或主体色系漂移；检查现有渐变、反射与各自宿主，而不以 CTA 尺寸更大、文字清楚或同属暖色放行。全实例范围及主体 L*/色差进入 `button-appearance-family`，接受条件见颜色规则第 1、8 节。
- 连续 Tab 与内容区沿真实接缝查看最终合成颜色，是否外层一致但深层底板断色；用对应原生空白像素核验，不能仅比较裸 RGB 或文案。跨卡片同层级同状态 Tab 再并排查看完整状态语言。
- 卡片顶部/底部、CTA 下缘及外围宿主的宽渐变过渡区，是否出现无依据的暗带、灰脏反射或不协调色块；不能只看按钮内部亮点。启用渐变的零 Alpha 色标 RGB 不能按隐藏通道忽略。

上述比较片段从同一新鲜原生截图派生，保持 1:1 比例、真实宿主、来源坐标与哈希；跨区域并排片段帮助发现关系问题，全页彩色/灰度/缩略图仍判断累计焦点。先定位差异及来源层，再给结论，不能先写 PASS 后配一句总结。对应范围遗漏、无法取得证据或关系失败均不放行；机器通过不能抵消视觉反证。用户指出真实失败后撤销相应视觉门禁并保存失败证据，修正后重新取证，不能沿用上一轮 PASS。

## 6. 状态、Icon 与交互层级

### KV 与 UI 的颜色一致性

按《颜色决策规则》第 3.0 节生成独立的 `themeColorConsistencyAudit`。等价实例/连续表面的对应通道关系仍由 `colorRelationAudit` 检查，二者分别验收：

1. 核对 `kvAnalysis.colorAnchors` 的名称、原图坐标、真实像素与空间角色，以及 `surfaceFamilyPlan` 和角色 Recipe 的引用。样本与锚点名称/角色不符、没有来源依据或来源角色不匹配，返回 Phase 2/3，不以“同属暖色、材质相同”放行。
2. 将 KV 原始区域与最终页面背景、卡片、容器和主要按钮/CTA 并排看彩色 1:1。分开记录原 Paint RGB、最终合成代表样本与冷暖/色相倾向；不要从字形抗锯齿、亮边或最鲜艳像素取代表色。按 `surfaceFamilyPlan.hueRelationshipPlan` 检查：默认同一或相近色相家族，明度、彩度与材质仍须形成可辨层次和醒目操作，不能要求按钮与背景同 Hex。
3. 检查深浅转换后的环境家族是否仍成立，已有氛围/纹理/反射有没有把大面积颜色带偏。`kv-contrast` 须有 KV 明确风格化撞色或用户要求的证据，并实际呈现清楚的颜色反差和主辅分工；普通景物多色、仅各自“来自 KV”、仅色值不同不能通过。既不统一又不形成明确撞色的淡蓝/淡绿大面积搭配为 FAIL。同时检查 Icon/按钮与 KV/真实宿主是否协调；金属色不以“够黄”判断成立，具体按《颜色决策规则》第 8 节。真正近中性/极暗样本以实际 RGB、冷暖和视觉倾向判断，不使用不稳定的单一 Hue 或固定角度阈值。
4. 彩色模糊图与缩略图检查全页累计色彩面积：主家族仍须主导，局部植被/反光/强调色不能经过大面积和高频重复成为无依据的第二主底色；撞色方案仍须清楚呈现反差和面积主次。灰度用于明暗，不能代替这项彩色检查。

记录锚点、实际节点/区域、截图、合成贡献与结论。真实家族漂移或关键疑点未验证时为 `FAIL → Phase 3/5/6`；返回受影响配方并使相关门禁失效。文字可读、目标通道数值正确及原稿关系一致均不能覆盖该 FAIL。

先逐项对照 `themeDecision.colorClarityPlan` 与《颜色决策规则》第 3.1 节，生成 `finalAudit.colorClarityAudit`。必须正向确认以下五项均满足，并附节点/截图证据：实际彩度足以表达 KV 和角色；页面/卡片/容器对比清楚；主要操作突出且状态可辨；文字/图形清楚；整页强弱关系和材质表现美观协调。只有“未发现发灰/过艳”、只有文字对比度数值、只有少量高光像素颜色鲜明，都不足以通过。保护色不参与新彩度目标，按第 8 节验收原稿一致性。

继续按《颜色决策规则》第 3.2–3.3 节核对 `colorClarityPlan.lightnessAndChroma`，把结论记在同一 `colorClarityAudit` 中：色相、彩度、感知明度、材质和背景关系是否分别满足角色目标。发现问题或关键不确定项时，须有针对具体维度的真实对照试色、调整变量及结论，不能以其他维度达标代替验证。不得仅因 KV 明亮就要求更亮按钮，也不得预设压暗或增艳；有充分视觉证据时不强制额外方向性试色。仅给 HSV 饱和度或仅说“饱满”不算证据；数值达标但视觉重量、受光或操作层级不合适，仍为 `FAIL → Phase 3/5`。授权参考设计师页面时，还须核对可见 Paint 与 IMAGE 分类、同角色比较、可迁移关系及结构/对比度限制；不得把未验证的参考数值视为达标。

验收强调色时同时核对饱和感/彩度与感知明度：有足够色彩力度，亮色鲜明、深色干净；不能以 HSV 饱和度高、文字对比度高或少量鲜亮像素替代真实观感。发现灰闷时分别定位彩度不足、明度压低或叠层冲淡，不默认只提高饱和度，也不把所有表面一起增艳。

### 关键数据

所有 KV 下，金额及任务/作品的强调数字按《颜色决策规则》第 6.1–6.2 节验收：颜色鲜明、突出、清晰，不因字号小而自动压暗为灰闷中间色。顶部收益卡可选鲜亮或干净深色；浅卡片上加深数字可用于突出，降低 V 本身不构成失败，也不机械跟随按钮/Icon 的亮暗方向。逐文字区间记录真实可读性与强调效果；仅启用严格标准时附对应标准结果，数值较高不能覆盖强调不足、灰闷或融入正文的失败。

### Tab

- `control-family-consistency` 独立验收跨区域同族控件：内容分类 Tab、榜单 Tab 等按层级/状态配对看原稿与新稿，共同目标配方及登记变体均实际读回并在真实宿主验证。同族原本同色却因卡片划分被拆色，或虽局部可辨但跨区域色彩语言明显漂移，均 FAIL。不同层级/状态不要求全部一个 RGB；源 RGB 不同但应共用新配方时用目标值校验。该规则 scope 覆盖全部相关控件根，需一次完整跨区域比较，不拼接各卡片单独的 PASS。
- 核对 `sourceColorRelations` 的原稿关系、预先登记的语义拆分及实际读回结果，生成 `colorRelationAudit`。原稿连续同色底板不能因节点类型不同而拆色；同色文字的状态 Alpha、前后表面差异及指示条角色按《颜色决策规则》第 9 节复核。查看原稿与结果的 1:1 对照，不能只验文字或旧色残留。
- 一级/二级 Tab 在实际尺寸下一眼可辨；Tab＋连续容器与外卡、选中/未选中底色、指示条与底色、文字与底色分别通过原稿基线检查，不合并为一个文字比值。
- 现有结构支持时优先使用两类选中信号；只有单一状态载体时按《颜色决策规则》第 9 节验证一类明确、稳定的信号，不为数量新增结构。
- 选中态纯色方向弱于邻近主要按钮，不使用大范围材质渐变。
- 状态不能只依赖普通文字同 RGB 的轻微 Alpha 差。

### Icon

- 所有需换肤功能 Icon 的 Fill 与 Stroke 均进入新主题；媒体/Logo/图片 Icon 与前三名受保护名次图形未改。
- Icon 容器弱于 Icon 图形、小按钮、Tab 选中态和 CTA，且没有直接复用高饱和按钮色后降节点 Alpha。
- 存在局部 Icon 底托时，按《颜色决策规则》第 7.1 节核对 `iconMaterialRecipe.container`：有独立颜色来源、图形/卡片关系与渐变职责；没有以“主色加白”代替判断，也没有为追求异色任意增加新色。允许有依据的辅助色、材质色或中性色，同主色不是验收条件。
- 图形、按钮与普通辅助底托均未被历史全模式 S/V 锁定规则限制；第 3.2 节浅→浅保留分支的适用范围明确，未扩大到其他宿主或底托；白色源底没有因 `S=0` 被固定改为中性灰或统一 V。分别检查实际底托与卡片的冷暖/色相关系、图形与底托的承托关系，不能仅凭轮廓清楚通过；确属明确锁定项或保护项的底托有职责依据。
- 实际尺寸下图形清楚，底托起到承托作用；整页重复排列的视觉权重合理，同族配方一致或变体有依据。底托可有柔和消隐边缘，不要求所有边界都强描边；同色混融或异色割裂时有针对性的试色修正。原渐变结构与透明度规则未因模仿参考而突破，前三名底托仍完全保留原 UI 配色。
- 多层 Icon 保留可感知明暗层次及原高光位置、方向和覆盖范围，仅在第 3.2 节保留条件或明确通道锁定适用时保持原 S/V，其他情况不锁定数值跨度；不同 Paint 没有被写成相同渐变或相近暗色。
- 实际尺寸下受光面、阴影、高光各自可感知；没有以层数相同或少量亮边代替材质成立的证据。参考图片的立体效果未被误报为目标矢量 Icon 已实现的效果。
- Icon 图形与容器、文字、按钮清楚区分，没有发闷、过深、材质消失或重复抢焦点。
- Icon 与按钮按《颜色决策规则》第 3.2 节核对已记录的目标 UI、KV 明暗与色彩力度、实际宿主和鲜亮/干净深色方向，检查来源与角色依据。H/S/V 读回应符合预先登记的目标值，浅→浅且背景不太淡的保留分支逐色标核对原 S/V/Alpha，其他明确锁定项也与原稿保持；若偏离该分支，须有仅换 H 失败的证据与必要调整理由；各级 Alpha、混合模式、渐变空间结构及保护项按对应规则核对。原稿/新稿同尺寸真实场景中，主体、暗部、高光仍可区分，图形清楚、操作醒目；机械压低鲜亮色造成灰闷暗块或不同色标截断同色均失败。加深或提亮本身不构成失败；不能用通道保持、层数相同或少量亮边代替实际显著性。

### 小按钮与 CTA

- 当前可用的全局 CTA 是最强操作焦点；卡片内主要按钮在局部强于类别栏、普通 Tab、标签、容器和装饰。按实际背景的 1:1 和整页缩略图检查整个按钮主体；主体与弱控件近似时不能仅因字可读或按钮尺寸大而通过。
- 小按钮与 CTA 属于同一交互/材质家族，但 Paint Recipe 不相同；CTA 是强化而非等比放大。
- 非操作色块的面积和重复频率没有形成更强累计视觉重量。
- 按钮没有与背景融为一体，未出现无光照依据的多色扩散、亮框吞没主体、与 KV 无关的大面积高饱和块等实际问题。不能仅因明亮、邻近色过渡或强高光而判“廉价/过艳”，也不能用降低饱和度或压暗全体角色作为默认修正。

逐项执行《颜色决策规则》第 8.1 节，生成 `finalAudit.buttonCompositeAudit`：

- 实际合成后的基底达到符合 KV 和操作角色的足够彩度与明暗力度，并有按钮主体、局部背景及邻近弱控件的代表区域证据；高光、反射没有把主体颜色冲成大面积灰白/奶油色而削弱焦点。局部亮边、自然反光和有依据的低饱和设计不因颜色浅而自动失败。
- 主要按钮相对真实页面/卡片背景有清楚的明度、彩度、色相或轮廓差异；在 1:1 与缩略图中都能辨认为当前操作，启用态与已有禁用态明显区分。
- 基底、高光、环境反射各有职责和可见差异；不能只因为保留了渐变层数或文字对比度合格就通过。
- 主体明度与受光感符合已记录的 KV 光照气质；既检查泛白失色，也检查压暗基底/反射造成的沉重。高光实际覆盖面积与有效贡献有截图证据，不以单一 Alpha 高低判好坏；不能为提高白字对比度而牺牲明快感后仍判视觉通过。
- 若有 `buttonMaterialAlphaOverrides`，按《颜色决策规则》第 8.1 节逐通道核对既有 Fill/Stroke/颜色 Effect 的材质强度差异及因果证据；原透明色标/关闭层未激活，原可见层未归零，基底不透明性、蒙版、节点/祖先 Alpha、几何和全部保护区未改变。
- 按《叠层合成审计》核对每个按钮的完整材质根、实际层级、蒙版作用范围与祖先/状态贡献；主体分区和面积证据不由局部亮边代替。用户明确要求明亮鲜明按钮时，暗沉版本不能以高饱和或深色风格理由通过。孤立白画布截图不等于真实深色宿主已验证。
- 浅色 UI 配淡色 KV 时，核对配方是否有来源且与浅宿主拉开差异，而非直接复用浅表面主色；深色方案按清晰度和材质验证，不以低 V 本身判失败。出现发灰、泛白、不合时宜的暗沉、与弱标签/禁用态近似或主要操作不突出时，必须有真实试色修正记录；仅提供一段“协调/克制/饱满”的理由不得判 PASS。判断与选定色相无关，金色或红色都按同样标准验收。

任一失败，`FAIL → Phase 3/5/6`。

## 7. 卡片氛围与材质

- 氛围只使用 `cardAtmospherePalette` 的环境色及邻近色；不含标题、人物、箭头、Logo、金属包边、按钮色或局部反光。
- 氛围位置符合《颜色决策规则》第 5 节的默认锚点或有依据的原空间家族；不为套位置规则移动图层。
- 按《颜色决策规则》第 5 节矩阵逐卡核对实际 `themeTransition`、稳定底色与完整氛围叠层：`light-to-dark` 有可感知局部有色受光，不能是白灰雾或暗块；`dark-to-light` 是干净浅底上轻量环境色，不残留旧深色端点/暗纹理形成的灰暗罩染。同模式保持空间配方，已登记材质强度例外逐项核对。
- 既有 SOLID 模糊光斑、GRADIENT、位图/滤镜、反射、底色羽化层都已分类；没有氛围的卡不凭想象新增氛围。ALPHA 蒙版灰色与 Boolean 操作数未误判为灰色表面，结构蒙版未改动。
- 多层在同一区域重叠后仍保持干净光色，不能凭单层饱和度、低 Alpha 或两种相邻 Hue 直接通过；核对最终主体/受光区、向稳定底色消隐及邻近按钮关系，不能只有一个鲜亮像素或一条亮边。
- 标题是稳定纯色或窄差渐变，只在边角有小范围受光，不与氛围、Icon、按钮共享大渐变。
- 深色方向性描边只用于规则允许的角色和转换，方向与 KV 光源一致；重复普通卡和内部异形层没有机械白框。
- 原稿已有金属/玻璃层次没有因换肤被压平；材质没有机械指定色相。

以上记入 `finalAudit.cardAtmosphereAudit`，包含逐卡覆盖、实际模式、层职责、合成截图和修正记录。旧紫、红棕、黄绿等冲突氛围即使低 Alpha 仍可见，也视为残留。失败时 `FAIL → Phase 3/5/6`，规则校验不得替代真实跨模式试色。

## 8. 媒体、前三名颜色保护和实例

- `protected-media-overlay` 的 Fill、Stroke、文字色、Paint/节点 Alpha、blendMode、mask 和 Effect 与原稿完全一致。
- 保护范围精确到封面内左上/左下标签、播放量及图标，不以媒体组件祖先整体排除。
- 封面外标题、副文案、普通标签和交互信息已换色并进入残留扫描。
- 按 `sourceAudit.protectedRankTop3` 与副本映射逐项核对前三名名次文字、奖牌/徽章、底托/领奖台和附属形状。Fill、Stroke、所有渐变色标/Alpha、多色 Vector region、Effect、相关图片参数及节点 Alpha/blendMode/mask 与原稿一致；不能只核对主色或数字。
- 保护项与代表/扩展写色集合按节点及属性/文字区间/Vector region 核对，无保护通道被覆盖；混合节点允许只写非保护通道。若有误改恢复，`protectedColorRestorations` 有原稿指纹和恢复后零差异证据。解绑后保护映射仍有效，无通过祖先 Alpha/滤镜/覆盖层间接改色。
- 前三名姓名、收益、榜单标题、外卡片、Tab 与第四名起的普通编号未因混合父级而被整组跳过。合法外背景变化造成透明边缘的合成变化不视为 Paint 修改，也不能以此为由改保护色。
- 只有计划内副本实例被解绑；解绑前后可见结构、尺寸、位置、顺序、文案和素材一致。
- 剩余换肤相关实例具有所有应换肤 Paint/状态已本地覆盖、保护 Paint 未改的证据，否则按需解绑；不要求受保护名次/形状进入新色板。

将前三名结果单列为 `finalAudit.protectedRankTop3Audit`，包含实际名次集合、源/副本节点映射、逐通道比对结果及 1:1 截图；无前三名时记录 `not-applicable` 与读取证据，不虚构保护节点。

失败时 `FAIL → Phase 1/6`。

## 9. 全 Paint 与渲染残留色

第一层遍历副本所有可见 Fill、Stroke、渐变色标、Effect 和低 Alpha 装饰；IMAGE Paint 使用既有分类，不得统一排除。

第二层检查整页和关键局部截图的实际像素，重点看：圆角/边缘细线、标题装饰、状态底色、异形容器、Icon 内部、KV 接缝和主题装饰位图。

只排除：精确 `protected-hero-controls` 功能叠层、精确媒体保护区、已核实的 `protected-rank-top3` 名次与形状配色、品牌专属色、真实成功/警告/错误/危险语义色，以及不可编辑内容媒体内部像素。前三名原有金、银、铜、蓝、紫等颜色均按原稿保留，不作为残留清除，也不用于扩展新主题色板。排行榜保护范围之外的内容、第四名起的普通编号和其他普通装饰仍参与残留扫描，不得整块排行榜跳过。

任何不属于新方案或上述排除项的旧 Hue，必须定位贡献节点并处理。已纳入角色色板并有依据的 Icon 底托辅助色、材质色及中性色，不因不同于环境主色就判为残留；不得在残留清理时统一刷回主色。属性扫描通过但截图仍可见旧主题色，同样 `FAIL → Phase 6`。

## 10. 五种视觉视图

必须查看：

1. 原稿和副本整页彩色图。
2. KV→首卡衔接及关键区域 1:1 图。
3. 灰度图：检查明度拓扑。
4. 轻度模糊/眯眼图：检查面积和重复频率。
5. 缩略图：检查第一视觉焦点。

关键区域覆盖实际存在的收益复合卡、KV 衔接/认证文字、卡片标题＋氛围＋Icon＋小按钮、一级/二级 Tab、媒体覆盖层、前三名保护区和 CTA；缺失角色带读取证据记不适用，不要求补造角色或截图。五种视图仍须覆盖真实结果，可从同一有效截图派生灰度/模糊/缩略图；不重复生成未变化的原稿视图。

必须主动判断：

- 页面实际重量是否符合 `targetSurfaceDepth`，未被主体高光漂白或边缘暗部压黑。
- 页面、卡片、容器层级清楚，且与 KV 稳定环境属于同一视觉世界。
- 全局/局部第一焦点符合 `targetSalienceOrder`。
- 页面达到 `colorClarityPlan` 的实际彩度、明度、受光感与对比度目标：主题色彩有力度、视觉重量符合 KV、各层清楚、主要操作突出、状态可辨；按钮合成后主体颜色与材质层次成立，整页关系美观协调。
- 标题、Icon、Tab、小按钮和 CTA 各有独立角色，没有共享同一渐变。
- 整页没有旧主题残色、廉价材质、多色扩散、透明叠层 Bug 或明显审美冲突。

任一视图失败都不能用数值合格覆盖；返回对应阶段修正。
