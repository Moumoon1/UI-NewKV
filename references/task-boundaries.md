# 目标、换肤边界与恢复

Phase 1P 读取“输入与目标”；Phase 1W 前读取换肤边界与结构原则；继续同一任务时再读取恢复章节。

## 输入与目标

接收一个 Figma Design 链接，以及一张用户提供的新 KV 图片或 Figma 中明确指定的新 KV 节点。

可选指定新 UI 模式：`requestedUiMode=light/dark/auto`，自然语言“新 UI 只看浅色／深色”即有效，无需使用字段名。用户明确限制模式时仅评估该模式，并在有依据的可行范围内覆盖不同交互方向；若指定模式经实际预览仍无法成立，说明具体冲突，不擅自换成另一模式。未限制时，按[《KV 色彩分析》](kv-color-analysis.md#ui-模式与连续深度)先判断模式可行性：大面积、连续且可延展的明亮环境可支持浅色 UI；仅主体、高光或局部光束明亮，而环境持续深暗时只提深色 UI。KV 下缘深色本身不否决浅色 UI，须单独验证衔接。只适合深色 UI 时，把方案名额用于有依据且明显不同的深色表面和按钮方向，包括画面支持的淡紫等明亮按钮，不以深浅微调凑数。用户从方案中选定的模式成为最终 `targetUiMode`。模式约束页面、卡片与内容表面的整体深浅，不表示每个 Icon、按钮都必须同样深／浅，也不要求修改 KV 图片。

目标优先级：

1. 用户当前唯一选中的、且经旧 KV 与 Hero 核实的顶层活动页 `FRAME`；**未选中画框不是阻塞条件**。
2. 链接 `node-id` 指向的、经同样核实的页面级 `FRAME`。
3. 链接 `node-id` 指向 `PAGE`（或只有文件链接）且没有合格选中画框时，只读检查该页顶层 Frame 的名称、尺寸、层级及旧 KV/Hero 证据；能唯一确认原活动页就直接复制到右侧换肤，不要求用户先选中。已有换肤副本不能仅凭位置或名称被当成原稿；无法唯一确认时才请求用户指明。

目标必须直接位于 Figma `PAGE` 下，并包含可确认的旧 KV 容器和 Hero 可见窗口。以下情况禁止创建副本：链接类型不符、多个合格候选仍无法区分、目标不是顶层 Frame、新 KV 不可访问/不可解码、旧 KV 图片 Paint 无法唯一识别，或在 KV 适配例外之外仍必须改动页面布局、文案、字体、信息结构、共享样式/变量或主组件。

## 换肤边界

默认只允许：

- 按[隐藏图层预处理](hidden-layer-preprocessing.md)，在完整快照前建立一次临时工作源并删除其中 `visible=false` 的子树；原稿和新 KV 不动，不再逐项询问。其余结构保护与完整采集要求从清理后的工作源建立。
- 正式交付复制一次已冻结的工作源 Frame（无隐藏项时为原稿），并只移动副本根 Frame 的 `x`，放到原稿右侧不碰撞的位置。
- 先识别新 KV 是单图还是由图片、矢量、文字和渐变共同组成的完整复合视觉单元；复合 KV 必须整组使用，不能只抽取内层“主图”。优先验证原尺寸/同宽顶部对齐直接使用；可完整适配时不缩图、不补底，KV 较矮留下的底部空间按其最下方区域颜色补纯色或渐变。下缘有明显纯色/稳定色系时，该色纳入背景候选并作为接缝依据；采用其他背景色时须平滑渐变衔接，不能硬切。底部杂色/具体图像没有可用过渡时，默认在副本上叠加页面背景色的透明→不透明渐变，融合图片下缘；KV 只读保护原素材和内部节点，不禁止独立过渡层，具体范围见第 5 节。超高时优先保留整组尺度与内部构图并截去下方高度；仅用户明确要求整图完整显示时以 `contain` 等比适配；功能叠层不自动扣除为留白。新 KV 自带的底部渐变保持原类型、方向、色标位置和终点，不能翻转或重建。保持 Hero 外框及下方 UI 布局，允许重设副本 KV 专用图片的 `scaleMode`、`imageTransform`、定位和尺寸；必要时增加独立主图载体、最小环境补底或独立接缝融合层。具体边界和计算以《Figma 执行规范》第 5 节为准。
- 修改副本既有 Fill、Stroke、渐变色标、文字 Paint 和已有带颜色 Effect 的颜色及允许的 Paint Alpha；只在副本解除上述颜色通道的旧变量/样式引用，使交付稿复制后不再重新引用旧主题色。
- 按《文字换色与恢复》登记普通 TEXT 自身的最小 Alpha 覆盖；不修改状态/祖先透明度，不改字体排版或精确保护文字。
- 解绑妨碍完整换色或 KV 适配的副本组件实例；解绑操作本身须保持可见结构、尺寸、位置、层级、文案和素材，之后仅执行已记录的换肤/KV 适配差异。原稿实例和主组件始终受保护。
- 使用参考文件明确列出的跨模式氛围转换、浅色→深色方向性描边和收益卡底部氛围 Fill 例外。
- 对已确认的禁用按钮，在最小完整按钮视觉单元应用相对正常态 `50%` 的整体有效透明度；不得改成另一套灰/米色 Paint，也不得重复叠加既有 50% 衰减。
- 新 KV 已烘焙旧 KV 标题、Logo 或主体时，将有证据的对应 `kv-asset-subtree` 整体透明度设为 `0`；独立主图载体启用后，原 KV Paint 可归零以避免旧图透出。功能型 `hero-adjacent-ui` 不得隐藏。

除此之外，布局、尺寸、圆角、坐标、Auto Layout、约束、裁切、层级、混合模式、节点顺序、文案、字体、素材、矢量/布尔/蒙版几何、共享样式、变量和主组件均不得改变。

### 不可丢失的结构原则

- UI 颜色必须写入真正参与渲染的 `visualSurfaceCarrier`，包括异形 Rectangle、Vector、Boolean、Ellipse、Frame 及其多层 Paint；不得因为语义父 Frame 没有 Fill 就漏改，也不得给 UI 空外层新增普通矩形底色。Hero 内记录在案的 KV 主图载体、补底和独立接缝融合层适用独立例外。
- 对每个相关节点建立 `paintPresenceMask`。除记录在 `kvFitPlan` 中的 KV 专属差异外，`light-to-light` 与 `dark-to-dark` 时，上色/不上色关系、Paint/Effect 类型和有效开关必须与原稿一致。
- 复合异形卡的前后表面、透明度、遮挡、混合模式和材质层职责属于结构。禁止用降低前景 Alpha 制造玻璃感。
- KV 上的返回、规则、钱包、客服、分享等功能入口属于 `protected-hero-controls`，保护位置、尺寸、形状、字体、文案、素材与状态。所有模式均保持已有底托的颜色、透明度及其他样式；上面的文字和功能图形允许调整前景色，但仅可用纯白 #FFFFFF，或新 KV 标题实际采用的亮色（标题为亮色时，如亮金色）。标题没有亮色时使用纯白；精确通道与取色依据按《Figma 执行规范》第 5.4 节登记；不迁移画风、不新增入口底板，不扩大到倒计时、周期或普通信息带。
- 视频封面内部左上角标签、左下角标签、播放量及其图标属于精确的 `protected-media-overlay`，完全保持原色。与头像/昵称贴附并表达用户身份或内容属性的标签属于精确的 `protected-content-identity-label`，如信息流中的“找搭子”，原底色、字色、描边和透明度保持不变；封面外标题、副文案及功能/状态/筛选等普通标签仍须换肤。保护只到对应节点、Paint 或文字区间，不扩成整张卡或头像行。
- 排行榜前三名的名次文字和对应形状属于 `protected-rank-top3`，与视频标签一样保留原 UI 配色，包括名次徽章/奖牌、底托/领奖台、描边、高光与附属装饰。保护须精确到节点或 Paint/文字区间，姓名、收益、榜单标题、外卡片和 Tab 不随之整组跳过；详细边界见《Figma 执行规范》第 3.1 节。
- 页面中独立存在、由定制插画/图片背景与促销文案共同构成且不承担通用卡片/列表/任务/奖励结构的营销 Banner，把创意背景、插画、图片和营销文案登记为 `protected-marketing-banner` 并保持原样；不得换色、滤镜染色或纳入旧色残留清理。Banner 内或紧邻 Banner 的独立可编辑 CTA、按钮和其他通用操作控件须从保护集合中剔除并继续换肤；只有烘焙在单图中的操作画面或用户明确要求整体保留时例外。必须结合语义、构图、比例和截图判断，不能只凭名称保护普通业务卡片或漏掉 CTA。
- 成功、警告、错误、危险仅在改变颜色会造成业务误读时保留；除上述前三名保护范围外，其他排名编号和普通装饰不自动受保护。
- 默认保持盲测隔离。除非用户明确要求参考设计师版本，不得读取相邻已完成页面的截图或颜色。

## 恢复同一次已选色任务

有临时工作源时，先按隐藏图层预处理记录恢复同一个 `workingSourceId`，同时核对原稿与工作源指纹；不重复创建、清理或混用清理前后的节点路径。

用户明确要求继续同一次任务时，先核对当前 `fileKey`、原稿/完整 KV 的身份及完整指纹、已选方案。可读取该任务的进度记录与已有审查配方；不得把这一路径称为独立盲测。输入全部一致时复用唯一原稿快照与已审角色/配方，直接恢复尚未完成的计划或验收阶段，不重新提案或重新分类已审通道；只有新增/变化的决策才加载对应选色参考。当前副本必须现场核查：存在则核对实际状态而不重放写入；不存在且用户要求继续交付时，可用相同已审配方建立一次新的恢复交付，必须如实记录原副本缺失。恢复运行仍使用独立的临时目录。

若上一轮完成清理后用户继续反馈，已确认方案和授权仍有效；原始证据缺失时在新 runWorkspace 重建一次当前原稿基线并核对身份/指纹，不扫描其他旧目录，也不因历史“一次读取”拒绝修复。已有副本继续使用，已选方案不重新提问；无法核对的旧审查须明确失效。

复用的是输入与决策，不是 PASS：以当前工具重新编译/投影和运行静态检查，完整可回收原生预演及真实宿主验收通过后才交付；旧截图只作已审依据，不能冒充本次预演/终审。用户此前要求的修正必须先并入冻结计划，不先复现旧缺陷再修。身份/指纹不符时，重新分析受影响范围，不能强行套用历史稿。用户否定整套观感或要求重新换色时，此恢复捷径失效：保留用户明确选择的模式/方向与硬性指定色，从原稿、新 KV 重新建立角色、材质与表面关系，旧目标色、节点分类和验收结论不得作为新计划输入。
