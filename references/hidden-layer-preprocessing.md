# 换肤前清理隐藏图层

这是每次换肤的默认预处理。用户选色后、Phase 1W 完整快照采集前执行；仅分析或修改 Skill 时不运行，不再逐层询问用途或确认删除。用户本次明确要求保留的节点优先。

## 范围

- 只处理已确认的目标 UI 子树，在临时工作副本上删除自身 `visible === false` 的节点；隐藏父节点整棵删除，其后代无需再次扫描或读取 Paint、文字、矢量几何。
- 不把 `opacity=0`、隐藏的单个 Paint/Effect、被遮挡、被裁切或画板外的节点视为隐藏图层。不要按名称、颜色或面积猜测删除。
- 保留用户原稿、新 KV 完整子树、共享主组件和其他页面。可见的金币、红包、喇叭等素材继续原色保护；目标 UI 中原已隐藏的素材属于本次清理范围。
- 实例内无法直接删除的隐藏节点，记录精确 ID 和原因并保留；不为减小数据而解绑整个实例或修改主组件。保留项仍完整采集，必要时走现成分包路径，不阻塞其余换肤工作。

## 执行与基线

1. 轻量遍历目标 UI 的 `id/visible/children`，遇隐藏根即停止下钻。不先采集全部隐藏内容来决定是否删除，也不再计算每个隐藏组占多少字节。没有可清理节点时直接沿用原稿为采集源，不创建额外副本。
2. 有隐藏节点时创建一次带本次运行标记的临时工作副本，放在不碰撞的位置；按结构映射在副本内清理上述隐藏根。记录用户原稿 `originalSourceId`、工作源 `workingSourceId`、删除根 ID、未能删除项及耗时到 `mutationPlan.hiddenLayerCleanup`。原稿只计算并记录紧凑完整指纹，不回传其隐藏节点大数据。
3. **先清理，后建立完整基线。** 清理后的工作源作为现有脚本的 `sourceFrameId/sourceId`，`source-before.json`、所有节点映射、分类、计划和指纹均从它建立。这里的“完整”指工作源中全部保留节点及其全部字段；禁止只从 JSON 删行或裁掉矢量字段，留下与 Figma 不同的树。
4. 利用已有原稿截图与工作源基线原生图核对可见外观；剩余可见内容的绝对位置、尺寸、文案和素材须保持。若某次删除影响可见布局，恢复该精确分支并登记保留原因，不反复删除整页重建。临时工作源与用户原稿的唯一允许差异是根位置和已记录的隐藏子树删除。
5. 原有预演、编译和正式写入仍使用既有工具，从冻结工作源生成交付副本；不复用清理前的路径、快照或 PASS。终审分别核对工作源冻结指纹及用户原稿原始指纹，不能只验证工作源就声称原稿未变。工作源保持不变，交付成功后按精确 ID 清理本次临时工作源；未完成时保留用于恢复，禁止盲目重建。

这个工作源是“Phase 1W 前不得复制”“一次正式副本”规则的专门预处理例外，不是提前换色或额外试稿。每次运行最多创建一个；恢复任务复用已记录且身份/指纹匹配的工作源。新 KV 中隐藏内容不受此例外影响。

## 传输与结果

先对清理后的快照使用普通无损压缩；仍超限时才用冻结清单分包。已建立基线后禁止为解决回传失败临时删节点，变更必须重新建立一致基线。报告实际删除根数、保留项及采集耗时，不把快照减少量当成 Figma 文件或图片资源的实际释放空间，也不承诺固定提速比例。
