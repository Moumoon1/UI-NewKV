# 叠层合成审计

存在按钮材质或卡片氛围时，Phase 1 前完整读取。本文负责叠层证据和覆盖方法；选色、深浅转换及允许差异由《颜色决策规则》定义。它不是重绘或改变节点层级的授权。

## 1. 先列全量，再去重

在 `sourceAudit.layerStacks` 中枚举全部小按钮、大按钮和卡片氛围，包括启用、待解锁、禁用及当前选中状态。动作文字用于寻找候选，必须再由轮廓、层级和截图确认；相邻高光、底托、外发光可能是语义按钮的兄弟，不能只截最近的文字父级。记录最小完整材质根及其实际背景。

每个实例记录完整局部材质与全部有影响的祖先。仅当 Paint/Effect、渐变空间、真实 Z 顺序、蒙版、祖先透明度、状态、几何及背景关系均等价时，可共享代表试色；颜色相同或名称相同不是去重依据。记录 `representativeCoverage` 的实例→代表映射及非等价原因，Phase 5 在完整局部场景覆盖每种配方，Phase 7 核对每个实例在实际上下文中的结果。场景范围、共享背景和失效条件只按[《局部试色与执行工具》](execution-workflow.md)第 1–2 节定义。

完整单元同时包含结构层和真正输出颜色的层：例如 Tab 的异形选中底板、后景未选底板、相连内容底板、内容内部列表/横向滚动 Frame、文字和指示条。沿可见连续区域追到最终承载层；列表宽于裁切窗口、内容被蒙版截取、或颜色来自深层 Frame，都不能漏登记。将全量颜色清单的每个通道归入一个主视觉单元，格式及机器检查见[执行工具第 4.8 节](execution-workflow.md#48-视觉单元与局部修正闭包)。被保护/隐藏的通道也登记，但不会因此获得写入权限。

关系按职责建立：连续同色表面、独立状态表面、嵌套容器、图形/底托、主体/高光/塑形暗部。独立胶囊、媒体图片和材质高光即使与底板同 RGB，也不自动并为连续表面。高光位置、受光面与暗部的分工须保留；跨模式调整明暗方向先在目标配方说明，不把所有层压成同一 RGB 或靠少量亮边掩盖暗沉主体。

## 2. 层级记录不能省略的内容

每层保存：ID/父级/路径、角色、存在及有效可见性、节点与祖先 Alpha、blendMode、Fill/Stroke 索引及其 RGBA、Paint opacity、完整渐变 transform/色标位置、可见颜色 Effect 及其 Alpha/模糊/偏移、裁切与绝对变换、蒙版类型/作用范围、Boolean 操作数身份。IMAGE 另记录分类、哈希、滤镜、Paint Alpha 及真实截图贡献。

- 读取实际前后顺序；子节点通常从后向前绘制，Auto Layout 的 `itemReverseZIndex` 可反转顺序。多 Fill 的视觉前后亦须由实际渲染或导出确认，不能把数组索引自行假定为统一顺序。
- `isMask=true` 不等于一层可见的灰色。ALPHA 蒙版取透明度，灰色 RGB 通常不是灰色罩染；LUMINANCE 蒙版不能套用该结论。读取同组后续兄弟及边界，确认真实作用范围。
- Boolean 子图形可能只贡献几何，不独立输出其灰色/彩色 Fill；不将其当作可见叠层计数。隐藏 Fill/Effect 不纳入当前贡献，也不在换肤时激活。
- 启用渐变中的零 Alpha 色标仍须作为插值端点核对，不等于隐藏 Paint。保留其 Alpha=0，其 RGB 随整条渐变重着色；只有整条渐变/祖先关闭或全部色标透明时才能按无贡献处理。羽化层的透明端与不透明端一起检查，疑似灰带时用仅改透明端 RGB 的同场景前后渲染定位，不凭端点数值宣称已证明原因。
- `visible=true` 且祖先可见仍不证明输出像素：还须检查变换后的轮廓与祖先裁切/蒙版交集。位于卡片外且完全被裁掉的图层不作为泛灰原因。
- 祖先 opacity 的乘积只是影响线索，不是所有场景的精确合成公式。隔离组、蒙版、裁切、SCREEN/LIGHTEN/OVERLAY/SOFT_LIGHT/MULTIPLY、模糊及位图都须按真实截图验证；不能用简单 NORMAL Alpha 推算后声称已复现 Figma。

## 3. 为什么单层鲜艳，叠完仍泛灰

同一像素上的独立 NORMAL 罩染，累计覆盖为 `1 - ∏(1 - alpha_i)`，不是 Alpha 简单相加。两层各 50% 的白色覆盖，累计覆盖 75%。以普通编码 RGB 的示意混合计算，#FF5628 叠一次变 #FFAB94，再叠一次变 #FFD5C9；原基底很鲜艳，最终仍可能失色。这是解释模型，不是参考按钮的实测，亦不适用于隔离组或其他混合模式。

检查以下贡献，而非只看色板饱和度：

| 贡献 | 可能的合成失败 | 需要区分 |
|---|---|---|
| 多层白/暖白/浅色反射重叠 | 主体大片泛白、发奶、彩度丢失 | 窄亮边、局部闪光与整面罩染不同 |
| 多种环境色在同一区域重叠 | 色相相消或混成脏灰/褐色 | 分区有色光与全幅撞色不同 |
| 深色端点、暗色位图、塑形阴影 | 主体或卡顶被大面积压暗 | 少量塑形暗部与旧暗底罩染不同 |
| 祖先透明度、状态容器 | 启用按钮近似禁用态 | 不擅自改业务状态或祖先 Alpha |
| 柔光/金属纹理与新基底不匹配 | 颜色单独正确、材质合成后发闷 | SOFT_LIGHT 灰色纹理不一律禁用 |
| 新背景与按钮太接近 | 看似暗淡、操作焦点丢失 | 属于背景关系，不必归咎于基底彩度 |

高光数量多、Alpha 大，或出现灰色 Paint 都不能直接判失败。必须知道它在什么位置、覆盖多少有色主体、与哪些层重叠，以及最后看起来怎样。

## 4. 试色和最终门禁

Phase 3 在 `themeDecision.buttonCompositeReview` / `cardAtmosphereReview` 中登记层职责、目标主体/受光/背景关系、风险层和拟比较变量；Phase 5 填真实配方、截图与结论，不新建重复顶层产物。

Phase 5 只对已完成换色的场景及其新宿主做判断；背景与邻近控件未准备好时先完成计划内上下文，不把旧新混合的半成品误判为配方失败。整页累计视觉重量与未扩展区域残留留到 Phase 7。

先读基底数值，再看完整渲染。为定位问题，在同一副本及既定白名单上比较只改变一个已登记材质层的非零强度/颜色版本，保留其他条件可比；必要时联调基底和文字并明确变量。不得在生产配方中隐藏、删除或归零原可见材质，不改变蒙版和结构，不另建试色页面。若没有实际分层渲染证据，只能写“预计贡献”，不能写成已测量的因果结论。

真实尺寸截图至少检查主体左/中/右、上沿受光、下缘与邻近背景，避免字形、抗锯齿和窄装饰亮边污染主体判断；结合不含文字的面积分布，不用一个最艳像素或三个点证明整块面积。可记录统一色彩空间的明度/彩度分布辅助对比，但不设跨色相的万能 HSV 门槛。浅色且干净、受光充分、操作清楚，与低彩度灰雾不是一回事；用户明确要求高饱和明亮时，须在其指定角色中保持鲜明主体色面积，不能以参考中另一个柔和按钮替代该要求。

卡片检查氛围与稳定底色的关系，核对原暗色端点、旧纹理、反射和模糊光斑是否仍贡献错误灰/暗色。底色羽化/遮缝层不作为第三种光色：其不透明端点须同步对应稳定表面，保留既定消隐关系，避免旧底色形成灰带或接缝。深浅切换只决定表面与环境光组织，不决定按钮也必须变深或变浅。孤立参考按钮放在白色画布上不证明它已在深色页面通过，必须到实际宿主背景试色。

最终 `buttonCompositeAudit` / `cardAtmosphereAudit` 必须列出覆盖数、材质/状态/背景分类、实际截图、允许 Alpha 差异、失败及修正记录。没有逐实例上下文核对、明确要求的明亮主体不成立、氛围叠加变脏灰，均 FAIL；文字对比度、层数保持或某个单层 S 达标不能抵消。规则格式校验不等于两种真实跨模式换肤已验证。
